## 原文规划（保留备查）

## 一句话

群聊第三栏不再是「一个熔炉终端」，而是 **两个可同时开的引擎**：本机 **Cursor CLI**（`agent` / `cursor agent`）和 **Oh My Co-Work 熔炉**（Grok）。默认都走 TUI，互不抢同一个 PTY。

## 目标

1. 第三栏顶部变成引擎切换（Cursor CLI | 熔炉），而不是「一个终端里切模式」。
2. 探测本机是否已装 Cursor CLI；没有就给安装引导，有就开独立 PTY。
3. 熔炉默认改成 TUI（`tui`），GUI 降成高级选项。
4. 两个引擎可以同时挂着：切走 Tab 不断会话。
5. 桌面窗口继续无边框 + 毛玻璃，终端字体跟主题走。

## 不做（本版）

- 不为了「像 Cursor」去重做整个 IDE。
- 不在本机再包一份 Cursor 安装程序；只探测、引导、拉起。
- 不把 Cursor CLI 和熔炉接到同一个 PTY 里来回切（那会串会话）。
- 不把 4.9 的群报告/文档中心大改塞进这一版。

## 信息架构（第三栏）

```
第三栏
  Tab：Cursor CLI | 熔炉
  Cursor CLI
    未安装 → 探测失败 + 安装说明 + 重新检测
    已安装 → 独立 PTY（cwd = 当前群仓库或工作区）
  熔炉
    默认 TUI（独立 PTY）
    高级：仍可切回 GUI（设置里）
```

群报告、文档中心、备注、炼化 **先不动**。4.8 只改「人怎么进两个引擎」。

## Cursor CLI

### 探测

- Windows：`cursor.cmd agent` / `agent.cmd` / `%LOCALAPPDATA%\cursor-agent\agent.cmd`
- macOS / Linux：`agent`、`cursor agent`（PATH）
- 探测失败不要假装已连接。

### 会话

- 单独 `kind`（建议 `cursor-cli`），不要复用熔炉 PTY。
- cwd：当前群绑定仓库；没有则工作区根。
- 环境变量带群上下文（群名、仓库路径），但不要把熔炉的 `OHMYCOWORK_FURNACE_*` 整套灌进去。
- 关 Tab 不断进程（跟现在熔炉一样常驻）。

### 安装引导

- 未检测到：第三栏给官方安装说明 +「重新检测」。
- 不在应用内静默下载 Cursor。

## 熔炉（相对 4.7 的变化）

- **默认表面：TUI**。新会话、新设置缺省都是 `tui`。
- GUI 仍可用，但从「默认工作台」降成「高级/兼容」。
- 系统提示词继续强调：TUI 是主表面；GUI 只是另一扇窗。
- 熔炉 PTY 与 Cursor CLI PTY **隔离**。

## 桌面窗口（继续 4.7 方向）

- 无边框 + 自绘标题栏。
- Windows：`backgroundMaterial` / `transparent`；macOS：`vibrancy`。
- 熔炉 TUI / Cursor CLI 都吃同一套主题字体（`--font-mono` 等）。
- 已有：拖到顶部最大化、双击标题栏、Windows 贴边半屏、记住窗口位置。

## 终端体验（建议本版做掉）

- xterm `fit` 已经有；补 `search`、`web-links`。
- 把文件拖进 TUI：把路径写进输入，而不是在 GUI 里开预览。
- 选中即复制 / 右键粘贴（桌面端）。

## 和 4.9 的边界

| 4.8 | 4.9 |
| --- | --- |
| 双引擎入口、默认 TUI、窗口材质、终端字体 | 群报告并进文档中心、炼化 skill、窄栏横排、托盘/安装包体验 |

4.8 落地后，第三栏应该让人觉得「这里可以开 Cursor，也可以开熔炉」，而不是「又一个内嵌聊天框」。

## 验收（4.8）

- [x] 本机有 Cursor CLI 时，第三栏能开独立会话
- [x] 没有 CLI 时有明确引导，不会假连接
- [x] Cursor CLI 和熔炉可同时开，切 Tab 不丢会话
- [x] 新用户默认进熔炉 TUI，而不是 GUI
- [ ] 无边框窗口在 Win/macOS 上材质正常，终端字不糊
- [x] 设置里炼化开关能看见、能保存（抽屉不被桌宠挡住）

## 风险

- Cursor CLI 命令名/安装路径随官方版本变：探测逻辑要集中、好改。
- 两个 PTY 同时跑：内存和 GPU（xterm）要盯一下。
- Windows conpty 对 Cursor CLI 的兼容性可能和熔炉 bash 不一样，要单独验。
