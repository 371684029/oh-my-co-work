| 属性 | 内容 |

版本号表示功能边界，不要求 Grok 或熔炉桌面形态在 `3.0` 一次完成。

---

## 1. 实施原则

1. 入口是 **精灵**（黑裙 Logo），不是按钮；先本机 Grok TUI，再客户端。  
2. 用户只有 **是否适配**；内部优先改代码，改不了再步骤标记。  
3. 改源文件前默认压缩包；标记不改会话气泡种类。  
4. 产品层 **统一管理员全部改称熔炉**；暂定只 Grok。  
5. 未配置也不隐藏精灵，提示下载并配置 Grok Build。  
6. JSONL 契约不改；流程轨用 Tab 标适配步骤。  
7. 只做极简 Agent；桌面就是精灵。

---

## 2. 版本切分

| 版本 | 主题 | 交付边界 |
|------|------|----------|
| `3.0` | 熔炉替换管理员 + 精灵入口 | 展示名/文案：统一管理员 → 熔炉；加人/加步骤仅「是否适配」+ hover；精灵三态；未配置提示装 Grok；可先嵌 Grok TUI |
| `3.1` | 适配落地 | 优先改代码（先打压缩包）；失败则步骤标记；流程轨 Tab；会话原样展示；三套角色 prompt |
| `3.2` | 工作流 prompt 工程 | 节点一览 + 当前节点合同；角色壳跟游标换挡；详见 [crucible-3.2.md](./crucible-3.2.md) |
| `3.3` | Grok Build 教程 | 未安装 / 未登录 / 未配置时展示下载登录配置教程；秘钥不进仓库 |
| `3.4` | 开熔炉注入 Grok | 点开 TUI 时写入本机规则 md + 短 `--prompt`；按主持/适配/审核换指令；详见 [crucible-3.2.md](./crucible-3.2.md) §10 |
| 后置 | Grok 客户端 | 从本机 TUI 拓到 Grok 客户端 |

`3.0` 就要能看见精灵，不要做空按钮。未接 Grok 时允许只提示配置。

## 5. Phase 2：3.1 适配落地

- [x] 勾选适配后：**先改代码**；改前打压缩包。  
- [x] 改不了则给该步骤打 **适配标记**（沿用原 step_type）。  
- [x] 会话框按原消息类型展示。  
- [x] 流程轨为带标记步骤加 Tab/标识。  
- [x] 尽量不影响源文件其它使用场景。  
- [x] 能接到 JSONL 的优先写侧通道。  
- [x] 三套作用各一份 prompt + 记忆：成员适配 / 节点适配 / 系统审核；本轮编译 `ACTIVE.md`。
- [ ] **3.4** Grok 专用 cwd + `AGENTS.md` 标记块；点开熔炉先写盘再 `--prompt`（§10）。

验收：开适配后用户不必选择路径；能改代码的成员有备份包；不能改的步骤在流程轨 Tab 里能找到，聊天形态不变。适配步与闸门不共用同一份记忆。

## 6. Phase 3：3.2 工作流 prompt 工程

设计全文：[crucible-3.2.md](./crucible-3.2.md)。原「Grok 客户端 / Build 式编码」后置，不挡开聊懂事。

- [x] 开聊编译 **节点一览**（类型/执行者/适配/闸门/状态/游标）+ 当前节点合同。
- [x] 角色壳跟当前节点标记换，不跟业务场景名换。
- [x] 适配步、熔炉闸门换壳时地图留下。
- [x] **开始执行后**游标每动一格就刷新当前节点合同（开跑 / 等人 / 完成），不灌聊天。
- [ ] 精灵点开时是否切主持（后置）。
- [ ] `step.hint` 人给某一格的短备注（后置，不作第二套编排）。
- [ ] **3.4** 开熔炉注入：见下方 Phase 5。

验收：开聊后 `SITUATION.md` 能看出每个节点是什么、游标在哪；不依赖某个业务场景词。

### 6.1 后置：Grok Build 式编码

- [ ] 设置中配置提供方与密钥（本机，不进 JSONL / 群报告）。  
- [ ] 熔炉「写代码 / 构建」任务启动 PTY 中的约定执行体，不直连一套无进程治理的沙箱。  
- [ ] 无 Grok 时不隐藏精灵，只提示下载配置。  
- [ ] 厂商暂定 Grok，不做切换 UI。

验收：一次「改文件 + 跑构建」在工作台终端可见、可停止、可进节点结果。

开放：Grok Build 具体安装包与配置项以当时官方为准。

## 8. Phase 5：3.4 开熔炉注入 Grok 本机规则

设计全文：[crucible-3.2.md](./crucible-3.2.md) §10。现状：`ACTIVE.md` 写在 gitignore 的 `data/furnace/`，启动命令仅为 `grok`，Grok **默认不读**该文件。

### 8.1 要做

- [ ] 熔炉 TUI 的 `scriptWorkDir` 改为专用目录（默认 `~/.grok/workspaces/oh-my-co-work/`，设置可改），不要用业务仓根、不要只用 `data/furnace/`。
- [ ] `activateFurnaceRole` 之后刷新 `{cwd}/AGENTS.md` 标记块（`oh-my-co-work-furnace:begin/end`）；可选同步 `.grok/rules/session.md`。
- [ ] 点精灵 / 开熔炉：先编译再写盘，再 `grok --prompt "…"`（按主持 / 成员适配 / 节点适配 / 审核四套短指令）。
- [ ] 设置：上下文路径、写入开关（默认开）、第一次确认、打开文件夹、移除标记块。
- [ ] 未装/未登录不写业务规则。
- [ ] 不覆盖用户全局 `~/.grok/AGENTS.md`；不按群模板分裂 skill。
- [ ] 群聊消息不刷新规则；开炉 / 开聊 / 换壳才写。TUI 已开时提示规则已更新。

### 8.2 验收

- [ ] 专用 cwd 下 `grok inspect` 能看到熔炉 `AGENTS.md` 或 `.grok/rules/session.md`。
- [ ] 开炉后标记块角色、当前节点与工作台游标一致。
- [ ] 标记块外的用户手写在刷新后仍在。
- [ ] 关掉写入开关后不再改用户 md。

## 9. 测试与安全（随 3.0 起）

- 熔炉闸门与人闸门同一套 `waiting_human` / 完成语义（或显式新状态，但不可无记录推进）。

- 熔炉桌面与浏览器工作台同一 Origin / 本机令牌模型。
