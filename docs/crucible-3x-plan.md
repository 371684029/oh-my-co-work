---

## 1. 实施原则

1. 先让熔炉出现在 **加人 / 建群 / 闸门配置** 上，再接云模型，再做桌面壳。  
2. 熔炉产出必须是普通成员、普通群模板、普通闸门记录；禁止只存在于精灵会话里的「影子工具」。  
3. JSONL Adapter 只扩展文档与示例，不在 3.x 改成「熔炉私有协议」。  
4. 写代码、跑构建仍走 PTY（及可选 Adapter）；不新增脱离 `processRegistry` 的执行通道。  
5. 默认闸门执行者仍是人；熔炉是可选项。  
6. 模型提供方可替换，Grok / Grok Build 不写进引擎内核硬编码。  
7. 桌面精灵与工作台共用本机 server；切换外壳，不切换数据面。

---

## 2. 版本切分

| 版本 | 主题 | 交付边界 |
|------|------|----------|
| `3.0` | 熔炉能被配上 | 内置熔炉成员（或 kind）；加成员 / 建群可选熔炉；闸门执行者可配人 \| 熔炉；无云模型时可用占位或本地规则 |
| `3.1` | 熔炉会适配、会造成员 | 生成包装脚本、成员 JSON、打开 JSONL；人（或熔炉闸门）确认后入群；失败降级为手填成员 |
| `3.2` | 熔炉能写代码 | 对接 Grok Build（或等价可替换提供方）；编码/构建在 PTY 内完成；无密钥则禁用此能力、适配仍可用 |
| `3.3` | 桌面精灵 | 托盘 / 随叫随到小窗；与工作台 TUI 可切换；同一会话与终端；不另起账本 |

`3.0` 不依赖 Grok。`3.3` 不依赖把所有闸门都配成熔炉。

## 4. Phase 1：3.0 可配置的熔炉

### 4.1 产品

- [ ] 设置或成员库出现「熔炉」（用户能理解这是可选执行者，不是新工作台）。  
- [ ] 新建成员：可选「请熔炉协助适配」（可跳过）。  
- [ ] 新建群模板：可选「请熔炉协助拼流程」（可跳过）。  
- [ ] 闸门 / 人工步骤：执行者可配 **人** 或 **熔炉**。  
- [ ] 熔炉处理闸门时，对话里仍有闸门卡与结果，和人处理同一套时序。

### 4.2 暂不做

- 不接 Grok。  
- 不做桌面精灵。  
- 不让熔炉默认批准所有闸门。

### 4.3 验收

- [ ] 不选熔炉时，加成员 / 建群 / 闸门与 2.x 行为一致。  
- [ ] 关掉熔炉成员后，已存在的群和脚本成员仍能跑。  
- [ ] 配成熔炉的闸门不会绕过节点状态机。

---

## 5. Phase 2：3.1 适配与创造

- [ ] 熔炉产出可落盘的包装脚本 + 成员配置草案。  
- [ ] 草案进闸门（默认人审；可配熔炉自审，但要能改回人审）。  
- [ ] 通过后写入与手建成员相同的表结构。  
- [ ] JSONL 侧通道路径按现有 `ACW_ADAPTER_*` 约定注入。  
- [ ] 适配失败：明确错误，用户可改回手填；PTY 仍可当 L0 终端用。

验收：用一个本地示例 CLI，经熔炉变成带 JSONL 的成员，提问能进闸门。

---

## 6. Phase 3：3.2 Grok Build 式编码

- [ ] 设置中配置提供方与密钥（本机，不进 JSONL / 群报告）。  
- [ ] 熔炉「写代码 / 构建」任务启动 PTY 中的约定执行体，不直连一套无进程治理的沙箱。  
- [ ] 无密钥或提供方不可用：编码能力关闭，加人适配仍可用。  
- [ ] 厂商协议变化时只换提供方模块，不改会话/节点模型。

验收：一次「改文件 + 跑构建」在工作台终端可见、可停止、可进节点结果。

开放：Grok Build 具体 API / 产品名以当时官方为准；本文只锁「可替换的编码构建提供方」。

---

## 7. Phase 4：3.3 桌面精灵

- [ ] 独立小窗或托盘入口，随叫随到。  
- [ ] 可切换回完整工作台（三栏 + 内嵌 TUI）。  
- [ ] 精灵内加人 / 建群 / 过闸门走同一 API。  
- [ ] 不维护第二份 SQLite。  
- [ ] 通知（构建完、闸门等人）后置可做，但不得替代闸门 UI。

验收：只开精灵能完成「叫熔炉适配一个工具并入群」；切回工作台能看到同一群、同一终端。

---

## 8. 测试与安全（随 3.0 起）

- 熔炉闸门与人闸门同一套 `waiting_human` / 完成语义（或显式新状态，但不可无记录推进）。  
- 熔炉不能提交任意 shell 绕过成员白名单（沿用 2.x：只跑批准的执行体）。  
- 云端请求不把本机 Token、Adapter 原文、完整密钥写入聊天默认可见字段。  
- 桌面精灵与浏览器工作台同一 Origin / 本机令牌模型。

---

## 9. 2.x 仍后置、不因 3.x 提前吞掉的

专用 Claude/Codex Adapter、服务重启接管 PTY、L3 工作流协同、条件分支并行。熔炉 3.1 用包装脚本 + JSONL 覆盖「多数 CLI」，不替代专用解析器需求时的另案。

---

## 10. 3.x 完成定义（封板口径，未到日期）

同时满足才可称 3.x 主题落地：

- 加人、建群可选熔炉；闸门可配熔炉；默认仍可全程不用熔炉。  
- 熔炉产出的成员可脱离熔炉运行。  
- 工作台 TUI 与桌面精灵可切换且共用数据（若 3.3 已做；若只做到 3.1/3.2，封板说明须写清精灵未做）。  
- 编码能力可关；JSONL 契约未被替换。  
- 文档：本文、README 路线图、脚本指南中的「熔炉产出成员」说明齐备。
