## 一、熔炉里的 Cursor CLI：复制 / 粘贴 / 选择（重点）

涉及：`web/src/components/terminal/TerminalView.vue`、`FurnaceWorkspace.vue`、`web/src/composables/useFurnaceWorkspace.js`、`terminalInput.js`、`terminalPrefs.js`。

### 1.1 现状梳理（为什么难用）

`TerminalView.vue` 只做了最小接入：创建 `Terminal`、`FitAddon`、`onData` 转发，**没有**任何键盘/鼠标/剪贴板层面的定制，也没有加载任何扩展。具体缺口如下，按对"复制粘贴"体验的影响排序。

### 1.2 复制

- [x] **CP-01 P0 [代码确认 · 5.2.0] `Ctrl+C` 永远是中断，有选区时也无法复制**
  没有 `attachCustomKeyEventHandler`，`Ctrl+C` 一律作为 `\x03` 发给 CLI。用户选中文本按 `Ctrl+C`，结果是中断/退出了 Cursor CLI 当前任务，且选区没复制进剪贴板。
  建议（对齐 Windows Terminal / VS Code 终端惯例）：
  - 有选区时 `Ctrl+C`（Win/Linux）与 `Cmd+C`（macOS）= 复制并清除选区；无选区时 `Ctrl+C` 才是中断；
  - 始终支持 `Ctrl+Shift+C` 复制、`Ctrl+Shift+V` 粘贴；
  - 复制成功给轻量提示（"已复制 N 字符"），空选区不覆盖剪贴板。
- [x] **CP-02 P0 [5.2.0 工具栏提示/复制可见/Shift 说明 · 强制选择提示 · 待实机验证] TUI 开启鼠标上报后无法用鼠标选择**
  Cursor CLI（类 Ink/终端 UI）常开启鼠标跟踪；此时 xterm 把拖拽当作鼠标事件发给程序，**选不中文本**。用户感知就是"复制不了"。
  建议：
  - 终端工具栏常驻提示："按住 `Shift`（macOS 为 `Option`）拖选"；设置 `macOptionClickForcesSelection: true`；
  - 提供"强制选择模式"开关（临时忽略 CLI 的鼠标上报），状态显示在状态栏；
  - 提供"复制屏幕可见内容 / 复制最近一次回复 / 复制整个会话"三个按钮，不依赖鼠标选择。
- [x] **CP-03 P1 [5.2.0 右键菜单：复制/粘贴/全选/可见/清屏 · 选中即复制 P2 待做] 没有右键菜单与"选中即复制"**
  右键行为是浏览器默认菜单（Electron 里甚至没有 Copy/Paste）。建议：自定义右键菜单（复制 / 粘贴 / 全选 / 清屏 / 复制最近回复），并提供偏好项"选中即复制"（默认关）与"右键粘贴"（Windows 习惯，默认开）。
- [ ] **CP-04 P1 [代码确认] 终端内容无法按"回复块"复制**
  对话回复在 TUI 里是一整屏重绘，选择区域容易带上边框/状态栏字符。建议基于 `liveText`（已有的 `furnaceGuiTranscript`）提供"复制该条回复（纯文本 / Markdown）"，GUI 视图每条气泡加复制按钮，代码块单独复制。
- [ ] **CP-05 P2 复制时的格式清理**
  复制内容保留 ANSI 导致的行尾空白与折行；应去除行尾空格、对软换行（自动折行）还原为同一行（利用 xterm 的 `isWrapped`）。

### 1.3 粘贴

- [x] **CP-06 P0 [代码确认 · 5.2.0 bracketed paste + 延迟 \\r · 待实机验证] GUI 输入框发送多行/长文本时没有使用 bracketed paste**
  `useFurnaceWorkspace.js` 的 `sendChat()` 直接 `emit('input', `${payload}\r`)`。GUI 里 `Shift+Enter` 产生的换行，会被 CLI 当作"回车提交"，**一条多行消息被拆成多次提交**；并且正文与结尾 `\r` 在同一次写入，很多 TUI 的"粘贴突发检测"会把 `\r` 当成粘贴内容的一部分而不是提交。
  建议：多行文本用 `ESC[200~ … ESC[201~` 包裹（CLI 未开启 bracketed paste 时降级为逐行 + 软换行序列），**正文写入后延迟 30～80ms 再单独发 `\r`**；上述时序做成可配置并有单测。
- [x] **CP-07 P0 [代码确认 · 5.2.0 chunkBracketedPaste] 分块发送可能把 bracketed paste 的转义序列切断**
  5.1.0 的 `chunkTerminalInput()` 按 4096 字符盲切，不识别 `ESC[200~` / `ESC[201~` 边界；序列落在块边界时 CLI 可能把残缺序列当普通字符输入（表现为屏幕出现 `[201~` 乱码、粘贴内容被提前结束）。
  建议：分块前剥离首尾标记，按内容分块，首块带 `200~`、末块带 `201~`；块间隔随 CLI 反馈（有回显/背压）自适应，而不是固定 25ms。
- [x] **CP-08 P1 [5.2.0 字符数+预览+熔炉跳过+bracket 计数] 粘贴确认框的触发条件不准**
  现在按"换行数 > 1"弹确认，但：① bracketed paste 开启时整段数据里还包含两端转义序列，计数含义不明确；② 对"不会执行"的场景（Cursor CLI 输入框里粘贴多行）也弹窗，反而打断；③ 超大粘贴只显示行数，没有预览与字符数。
  建议：确认框显示字符数 + 前 3 行预览 + "不再提示"；按目标程序区分（shell 提示符才有执行风险）；默认策略改为"仅在检测到 shell 提示符且含换行时确认"。
- [x] **CP-09 P1 [5.2.0 熔炉 TUI 拖放/粘贴文件→inbox+路径写入 · 截图二进制待实机] 图片 / 文件粘贴在 TUI 里不可用**
  GUI 输入框能接收粘贴的文件并落到 `inbox/`（`onPaste`），**TUI 终端里没有对应处理**：截图粘贴无反应；拖拽文件到终端也无反应（Cursor CLI 本身支持引用路径）。
  建议：TUI 容器同样监听 `paste`/`drop`，文件落盘后把**带引号的绝对路径**以 bracketed paste 写入当前输入；Windows 路径含空格要正确转义。
- [ ] **CP-10 P1 [代码确认] GUI 的"附件"是路径文本，不是真正附件通道**
  界面已声明"不是官方附件通道"。建议在 Cursor CLI 模式下改写成其支持的引用语法（如 `@相对路径`），并校验文件确实在 CLI 工作目录内。
- [x] **CP-11 P2 [5.2.0 桌面 clipboard IPC + execCommand 回退] 剪贴板权限与回退**
  `navigator.clipboard` 在非安全上下文/权限拒绝时会失败；桌面端应通过主进程 `clipboard` IPC 读写（预加载 `preload.cjs` 暴露受限 API），网页端失败时回退 `execCommand`。

### 1.4 显示与输入质量（影响"能不能顺手用"）

- [x] **CP-12 P0 [代码确认 · 5.2.0 Unicode11 addon] 未加载 Unicode / 宽字符支持，中文与 emoji 易错位**
  `TerminalView.vue` 只加载 `FitAddon`；未使用 `@xterm/addon-unicode11`（且 `allowProposedApi: false`）。CJK、emoji、组合字符的列宽计算不准，Cursor CLI 的边框和光标会错位、选区偏移，复制出来也会多/少字符。建议启用 unicode11（需 `allowProposedApi: true`）并以 `activeVersion = '11'` 生效。
- [ ] **CP-13 P1 [代码确认] 使用默认 DOM 渲染器**
  大量输出和全屏重绘时滚动与选择明显卡顿。建议加载 `@xterm/addon-webgl`（失败回退 canvas/DOM），并在设置里可切换；注意上下文丢失事件的恢复。
- [x] **CP-14 P1 [5.2.0 WebLinksAddon http(s)] 链接不可点击**
  未加载 `@xterm/addon-web-links`；Cursor CLI 输出的 URL / 文件路径无法点击。建议：URL 用系统浏览器打开；`path:line` 在文档中心/系统编辑器中打开（复用 `docs-path-link` 的路径识别逻辑）。
- [x] **CP-15 P1 [5.2.0 SearchAddon + Ctrl+F] 没有终端内搜索**
  无 `@xterm/addon-search`。长输出里找内容只能靠肉眼；建议 `Ctrl+F` 终端内搜索（高亮、上下一个）。
- [ ] **CP-16 P2 [代码确认] 字体与行距不可配**
  字体栈、`lineHeight: 1.35`、`letterSpacing: 0.2` 写死，仅 `fontSize` 可调；中文等宽字体回退不理想。设置里补字体、行距，并提供"终端缩放 Ctrl +/-/0"（独立于全局界面缩放）。
- [x] **CP-17 P2 [5.2.0 工具栏「到底部」· scrollback 仍默认 5000] `scrollback` 偏小且无"回到底部"**
  默认 5000 行，Cursor CLI 长回复易被截；终端被滚动上去后没有"回到最新"按钮（GUI 视图有，TUI 没有）。
- [ ] **CP-18 P2 IME 与组合输入**
  需实机核对：组合态候选框位置、`compositionend` 后的提交、与确认框/序列器（`createInputSequencer`）的交互（组合期间不应被当作一次粘贴）。

### 1.5 验收（本章）

- 在熔炉 Cursor CLI 里：选中一段文本 → `Ctrl+C` 复制成功且**不中断**任务；无选区 `Ctrl+C` 仍可中断。
- 粘贴 20KB、含中文与代码块的多行文本：**一次完整进入输入框、不被提前提交、不出现 `[201~` 残片**。
- TUI 内粘贴截图 / 拖入文件：得到可用的路径引用。
- 中文、emoji 边框不错位，选区与复制内容一致。
- 以上场景有自动化用例（xterm 无头 + 模拟剪贴板）与一份实机检查清单。

## 二、熔炉（GUI / TUI 双表面、多 Agent）

涉及：`FurnaceWorkspace.vue`（~1200 行）、`useFurnaceWorkspace.js`、`shared/ptyPlain.js`、`server/src/furnace*.js`。

- [x] **FUR-01 P0 [5.2.0 cursor profile 去框线噪声 · 黄金样本/结构化通道待做] GUI 视图靠解析 TUI 屏幕重建对话，Cursor CLI 的版式未必能解析**
  `furnaceGuiTranscript(replay)` 把终端回放还原成文本再切成气泡，启发式明显是围绕 Grok 的输出格式调出来的。Cursor CLI 的布局、思考/工具调用块、状态栏不同，GUI 容易丢字、重复或混入界面字符。
  建议：为 Cursor CLI 单独的解析 profile（用真实录制样本做黄金测试）；解析不可靠时在 GUI 顶部提示"建议切到 TUI"；长期方向是接 Cursor CLI 的结构化输出（若提供 JSON/stream 模式）而不是解屏幕。
- [x] **FUR-02 P1 [5.2.0 切 GUI 不再 emit resize] 切到 GUI 会把 PTY 强制改成 120×40**
  `watch(surface)` 里 `emit('resize', { cols: 120, rows: 40 })`。切回 TUI 之前终端尺寸被改过，TUI 重绘错位，必须再触发 `fit`。建议：GUI 不改 PTY 尺寸（用独立解析尺寸），或切回 TUI 时强制 `fit` + SIGWINCH 重绘。
- [x] **FUR-03 P1 [5.2.0 Cursor/Grok 欢迎与状态文案] 文案仍以 Grok 为中心**
  欢迎页"本机 Grok 已接进协同台"、输入框提示"同一条 grok"、失败说明只写 `cursor-agent`/`grok` 两条通用语。选择 Cursor CLI 时应使用对应品牌、安装与登录指引（并带"复制安装命令""打开登录"）。
- [x] **FUR-04 P1 [5.2.0 仅 furnaceAgent + 熔炉成员判定] 单会话双 Agent 的状态混在一起**
  `isFurnaceTuiContext()` 靠正则匹配命令/标签判断是不是熔炉终端（`/(grok|cursor-agent|cursor)/`），名称含 `cursor` 的普通终端会被误判。应改为服务端下发明确的 `furnaceAgent` 字段，前端不再猜。
- [ ] **FUR-05 P1 "新开熔炉"会清上下文且没有预期管理**
  关闭/新开的确认文案分散在各处；缺少"保存当前对话记录再新开"与"上下文剩余量提示"。建议新开前自动归档对话到文档中心，并显示上下文长度估计。
- [ ] **FUR-06 P1 [代码确认] 快捷键只在"熔炉聚焦时"有效**
  `Ctrl/Cmd+1/2` 切 Agent 的作用域不清晰，与终端内 `Ctrl+数字` 可能冲突。统一快捷键层并提供设置页清单。
- [ ] **FUR-07 P2 状态感知**
  精灵/状态文案只区分闲置、工作、等人；应接入"等待审批 / 等待登录 / 网络错误 / 额度不足"等具体状态（从 CLI 输出特征与退出码推断）并在顶部横幅提示下一步。
- [ ] **FUR-08 P2 拆分 `FurnaceWorkspace.vue`**
  模板里内联 SVG 与大量元信息渲染，样式 1000+ 行。拆为 `FurnaceHeader / FurnaceChat / FurnaceTui / FurnaceComposer`，并把元信息解析（`getTurnMeta`）抽成可测纯函数。

## 四、炼化与还原

涉及：`server/src/refineSource.js`、`adaptBackup.js`、`refine.js`、`web/src/views/settings/Members.vue`。

现状：勾选炼化并保存时，会**直接改写用户的源脚本**（插入 `ACW-REFINE` 契约块），先把待改文件打成 zip 放进 `data/backups/refine`，路径记在 `config.refine.refineBackup`。

- [x] **REF-01 P0 [代码确认 · 5.2.0 restore API + 设置页按钮] 没有"还原"入口**
  备份 zip 只写不读：没有还原接口，成员设置页也没有"还原到炼化前"按钮；取消炼化只会把 `enabled` 置 false，**契约块仍留在用户源码里**。用户只能手动解压 zip 覆盖。
  建议：
  - 服务端 `POST /api/members/:id/refine/restore`：优先按备份 zip 原样还原；备份缺失时按 `ACW-REFINE` 起止标记**精确剥离**契约块；
  - 设置页成员详情提供"还原到炼化前"，展示将被还原的文件列表与差异摘要；
  - 取消炼化时询问"是否同时还原源文件"（默认还原）。
- [x] **REF-02 P0 [代码确认 · 5.2.0 暂存 manifest + 失败回滚] 改写不是原子的，中途失败会留下半成品**
  `applyRefineOnMemberSave` 对多个文件循环改写，任一文件失败时 `break`，已改的文件**不回滚**，状态里 `patchReason: 'patch_failed'` 但 `patched` 里保留了已改列表。
  建议：先全部生成新内容、校验后再统一写入（临时文件 + 原子替换）；失败自动用刚做的备份回滚，并把失败原因明确告知用户。
- [x] **REF-03 P1 [5.2.0 refine/plan API + 保存前确认框 · diff 视图待补] 写入前没有预览/确认**
  保存成员即静默改源文件。建议在保存前展示"将修改以下文件、插入以下内容"的 diff 预览，用户确认后再改；提供"仅记录规格、不改源文件"的选项。
- [ ] **REF-04 P1 [代码确认] 备份只覆盖"需要改的文件"，且无校验与保留策略**
  zip 无完整性校验、无 hash 记录，也没有上限清理；同一文件多次炼化只会保留首次备份的路径引用。建议：备份清单（路径 + sha256 + 时间）、还原前校验当前文件是否被用户后续修改（有修改则提示三方合并/另存）、保留最近 N 份。
- [ ] **REF-05 P1 编码与换行保持**
  写入使用 `utf8`，BOM、CRLF/LF 混合、非 UTF-8（如 GBK 脚本）文件有被破坏的风险（`nlOf` 只探测换行风格）。需对非 UTF-8 文件直接拒绝并提示，保留 BOM。
- [ ] **REF-06 P1 台账可追溯**
  文档中心里的炼化产出缺少"来自哪次运行 / 哪个成员 / 哪个备份"的元信息；应在台账头部写入，并提供"回到这次运行前的源码"的链接（对应 REF-01 的还原）。
- [ ] **REF-07 P2 外部 Agent 炼化 Skill**
  `POST /api/docs/refine` 缺少幂等键与速率限制，重复调用会写出重复台账；加入 `requestId` 去重与大小上限。
- [ ] **REF-08 P2 回归测试**
  补用例：多文件部分失败回滚、取消炼化还原、CRLF/BOM 保持、二进制/不可注释类型跳过、备份缺失时的剥离还原。

### 入口不够醒目（优先做）

现状（读代码确认）：
- 顶栏主导航只有「工作台 / 设置」，**没有文档中心入口**；
- 唯一入口是工作台右栏的小号 Tab「文档中心」，与「流程」并排、同样的弱样式，默认停在「流程」，新用户很难发现；
- 要进入完整的三栏文档页，还得先点进该 Tab，再点其中的「新标签打开」，两步且第二步按钮是次要样式；
- `openDocsHub()` 用 `window.open(..., '_blank')`：桌面（Electron）里会弹出一个**独立子窗口**，没有托盘/全屏/缩放等主窗口行为，且主进程未设置 `setWindowOpenHandler`；
- 产出文档时没有任何提示（无红点、无计数、无"新台账已生成"通知），用户不知道文档中心里有东西。

- [x] **DOC-11 P0 [5.2.0 顶栏 + Ctrl/Cmd+Shift+D] 顶栏常驻入口**

  桌面端不再 `window.open`，改为主窗口内路由切换（保留"在新窗口打开"作为次要操作）；同时在 Electron 主进程设置 `setWindowOpenHandler`：本机来源在受控窗口打开、外链交给系统浏览器。

## 六、页面样式与布局

- [ ] **UI-01 P1 [代码确认] 设计 token 不成体系**
  `styles.css` 约 1000 行，仅 ~34 个 `--ecw-*` 变量；各 `.vue` 内大量硬编码颜色（`FurnaceWorkspace` 约 58 处、`Workbench` 46、`FlowRail` 43、`ComposerPanel` 42、`DocsHub` 29）。建议建立 token（色彩、字号阶梯、圆角、阴影、间距），逐页替换，为深色模式与"降低特效"铺路。
- [ ] **UI-02 P1 [代码确认] 字号过小且不统一**
  大量 9～11px 文字（`FlowRail` 16 处、`DocsHub` 10 处、`FurnaceWorkspace` 10 处），桌面高分屏尚可，普通屏难读。建立字号阶梯（最小 12px），把辅助信息改用颜色/位置区分而不是缩字。
- [ ] **UI-03 P1 [代码确认] 响应式几乎缺失**
  全站 `@media` 仅寥寥几处，窗口最小 1024×600 时三栏会挤压。定义断点：≥1440 三栏全显；1100～1440 右栏可收起为抽屉；<1100 左栏收起；右栏/左栏宽度可拖拽并记忆。
- [ ] **UI-04 P1 毛玻璃性能**
  到处使用 `backdrop-filter: blur(36px)`（`DocsHub` 每一栏），远程桌面/集显下滚动掉帧。提供"降低特效"开关（关闭模糊、改纯色背景），并在三栏同屏时减少叠加层。
- [ ] **UI-05 P2 深色模式**
  跟随系统；先覆盖终端外壳、熔炉、文档中心（阅读场景需求最强）。
- [ ] **UI-06 P2 缩放控件联动**
  4.9.1 的缩放控件与桌面菜单、`Ctrl +/-/0` 快捷键同步；缩放后满屏终端（Teleport）与精灵位置回归检查。
- [ ] **UI-07 P2 组件一致性**
  按钮尺寸/圆角/悬停态、空状态、加载骨架、Toast 位置统一，沉淀 `ui/` 基础组件（Button、Chip、Empty、Panel）。
- [ ] **UI-08 P2 图标**
  现用 emoji 与字符（`📁 👥 ⛶ ↙`）当图标，跨平台字形不一致。换成统一 SVG 图标集。
- [ ] **UI-09 P2 无障碍**
  图标按钮补 `aria-label`、对比度检查（浅灰 `#86868b` 在白底不达标）、键盘可达的抽屉/菜单。
