# 4.7.0 ~ 5.0.0 桌面化与架构演进大纲

## 核心目标
解决目前存在的遗留痛点（系统通知弹窗强干扰、UI 组件与业务逻辑耦合重），并稳步推进重构与桌面化演进。
为了保证项目稳定性，优化动作将按照小步快跑的节奏划分为多个子版本，分别聚焦于：**通知与体验优化**、**前端解耦**、**引擎模块解耦与事件化**、**面向桌面端的全量融合**。

---

## 🚀 版本 4.7.0：体验治理与通知降噪（已完成）
本版本首要解决核心的体验痛点，将不适合 Web / 伪桌面壳的强阻断或原生系统级通知行为剔除。

- **关闭强干扰更新通知（降级为轻提示）**
  - 默认状态下依然开启后台静默检查 (`startupUpdateCheck: true`)，保证用户不遗漏新版本。
  - 将原生风格强阻断的 `ElNotification` 提醒降级，改为使用温和且不遮挡主界面的 `ElMessage.info` 进行轻提示。
- **配置分离**
  - 在 `web/src/composables` 新增 `useAppConfig.js` 封装状态管理，将更新检查状态下沉，不在视图组件生命周期里硬编码。
- **清理演示废弃代码**
  - 检查并移除无用的测试/演示遗留 UI 组件，保证主干视觉更清爽。

---

## 🛠 版本 4.7.1 - 4.7.x：前端架构瘦身与局部解耦
在这个微小版本迭代中，继续 3.8.1 的拆分工作，解决目前页面（特别是工作台）因为承载太多功能导致的臃肿问题，提高代码可读性和可维护性。

- **根组件拆分与状态下沉**
  - **App.vue 重构**：抽离启动检查逻辑、Grok 环境探测、全屏检测等为专门的 Boot 钩子 (`composables/useAppInit.js`)。
  - **Pinia / 全局 Store 引入**：逐步替换现有直接通过 `reactive/ref` 暴露状态的硬编码模式，使得子组件（如 Workbench, FlowRail, Settings）状态管理更为规范和可追溯。
- **组件级解耦**
  - 拆分 `Workbench.vue` 内部极其复杂的终端生命周期管理、布局逻辑。利用 Provider/Inject 将终端控制 API (`terminalStatus.js`) 和页面 (`SessionRail` 等) 安全解耦。

---

## ⚙️ 版本 4.8.0：核心引擎重构与隔离（中期目标）
该版本专注于 Server 端 (Node 引擎) 的健壮性优化。由于之前的逻辑重度耦合，解决“状态写入与行为触发混杂”导致的潜在并发竞态问题。

- **Engine 事件总线化 (Event-Driven Engine)**
  - 将 `server/src/engine/` 下状态机流转 (如 `advance.js`, `gates.js`) 导致的“副作用”（数据库修改、Websocket 广播、Markdown 日志生成）抽离出来，全部改为 `EventEmitter` 抛出标准事件。
  - 设立一个统一的 `EngineListener` 或者状态副作用中心，通过监听事件来进行状态持久化，避免四处操作 `db.js`。
- **依赖注入机制 (Dependency Injection) 的引入**
  - 将 `db` 实例、`better-sqlite3` 以及文件读写能力从全局模块状态改为基于 `Context` 的注入模式。
  - 为 `runners.js` (负责适配不同的执行模式和管线) 和 `terminalService.js` 增加依赖反转设计，提升自动化测试（Test Runner）时的易用性。
- **多终端/多会话隔离支持**
  - 修改 `processRegistry.js` ，支持在未来的标签页体系中真正管理相互隔离的多终端生命周期，避免交叉污染。

---

## 🖥 版本 4.9.0 / 5.0.0：面向桌面化基建的融合 (长期目标)
完全演进为一个正式的桌面形态（托盘独立窗、跨平台原生应用）。

- **桌面环境生命周期探测 (Desktop Environment Detection)**
  - 规划 `ACW_DESKTOP_ENV` (如 Tauri / Electron / WebView2)，启动时自动探测，如果处于桌面环境则向应用层提供特定 API（例如：原生右下角系统通知 API，区别于 Web 浏览器的 Notification）。
- **原生能力对接 (Native Capabilities Integration)**
  - 提供系统托盘 (Tray) 支持、最小化到托盘功能。
  - 允许在托盘右键通过“快捷命令”拉起指定的 Workflow（不再仅限于打开 GUI 面板操作）。
- **平滑静默自更新 (Smooth Auto-Update Pipeline)**
  - 打通下载、解压、覆盖、重启的全流程，实现类似 Cursor / VSCode 的静默后台增量/全量更新，告别每次需要让用户手动打开浏览器点更新的行为。
