# 5.7.0 需求文档 — 打包链路一劳永逸与发布治理

> 状态：**进行中** · 生成日期：2026-10-27
> 本文档汇总「桌面包启动失败 / 打包经常失败」排查后**仍残留的风险项**，作为 5.7.0 需求的单一事实源。
> 完成一项即在本文件打勾（`[x]`），并在「来源」列注明落地的提交 / PR（维护约定见「六」）。

---

## 一、目标与范围

**一句话**：让「打包 → 发布 → 用户下载启动」这条链路**失败即在 CI 报红、而不是在用户机器上才暴露**，并把发布产物彻底移出 git。

**5.7.0 要解决的问题**（5.6.x 已修复 Electron 主进程漏打包 `./lib` / `@acw/shared`、better-sqlite3 ABI 不匹配、白屏 TDZ 等直接故障，以下为剩余风险）：

1. macOS 包用普通 `zip -r` 压缩，`Electron.app` 内 Framework 符号链接被展开，解压后无法启动。
2. Linux 在 Ubuntu 23.10+（AppArmor 限制非特权 userns）上 Chromium 沙箱初始化失败，桌面包闪退。
3. `server/config/app-settings.json`、`slash-commands.json` 写在安装目录：只读安装 / 覆盖升级会丢配置，运行一次就弄脏 git 工作区。
4. `packages/*.zip` 由 CI 回推进 git：仓库历史膨胀（`.git` ≈ 379MB）、push 冲突、矩阵 job 互相覆盖。
5. 发布校验对「commit 不一致 / sidecar 不一致」只告警不失败，可能把旧包当新包发出。
6. 首屏 JS 过大（入口 chunk 918KB / gzip 299KB）。
7. 内嵌 Node / Electron 版本散落在脚本与 workflow 多处，升级易漏改导致 ABI 错配。
8. CI 只打 win32 桌面包；macOS / Linux 桌面包无 CI 产出、无启动冒烟；Actions 仍在 node20 运行时（即将弃用）。
9. 打包依赖 GitHub 下载 Node / better-sqlite3 预编译，网络抖动即失败。
10. `latest` Release 先删后建，窗口期内下载链接 404。

**开发策略（2026-10-27 起）**：Web / Linux / macOS 功能冻结，只修阻断性 bug；全部精力投入 Windows 桌面端最小可用（详见根 `README.md`「当前开发策略」）。下文非 Windows 项（PKG-12 macOS 签名等）顺延至解冻后；**PKG-14 优先做 Windows runner 启动冒烟**。

**不做什么**：见「七、暂不做」。

优先级：**P0** = 5.7.0 必须完成；**P1** = 强烈建议本轮完成；**P2** = 时间允许再做。

## 三、非功能需求

| 维度 | 要求 |
|------|------|
| 可靠性 | 打包 / 发布任何一步异常都必须让 CI 失败，不允许「告警后继续发布」 |
| 可验证 | 每个桌面包发布前至少经过 `verify-pack` 结构校验；linux 包经过真机启动冒烟 |
| 可维护 | 运行时版本只改一处；新增原生依赖必须进 `verify-pack` 检查 |
| 体积 | 入口 chunk gzip ≤ 260KB；xterm 等重依赖保持懒加载 |
