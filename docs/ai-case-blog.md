## 三、案例正文

### 1. 这是什么

`oh-my-co-work` 是一个**本地优先的群聊式多智能体协同工作台**。

产品隐喻故意写得很土、很好记：

- 一个 **Workflow = 一个群聊**
- 一个 **Agent / 脚本 = 一个群成员**
- 关键决定（启动、参数、审核）是**人工闸门**，不是弹窗附录
- 执行可以是普通命令，也可以是**真实 PTY 里的交互式 TUI**
- 需要改代码时，点右侧桌宠打开 **熔炉**：工作台用 node-pty 托管本机官方 `grok` CLI，不自研一套 Chat API

它不替代 Cursor 或 Grok，也不做云端多租户。引擎、界面、SQLite、Markdown 台账全部跑在本机。启动时可以向 GitHub Releases **只读**查询版本号（设置可关），不上传会话、成员配置或使用统计。

当前发布线是 **4.2.0**（2026-09-02）：1.x 群聊工作台、2.x 终端守护者、3.x 熔炉、4.x 协同文档中心与更新/备份，均已封板可用。

### 2. 为什么做：散落的自动化，装不进一条记忆

很多自动化仍然散落在 BAT、PowerShell、CLI、TUI 和不同 Agent 里：

| 痛点 | 现场长什么样 |
|------|----------------|
| 能力碎片化 | 脚本在终端，决策在聊天，进度在人脑 |
| 状态不可见 | 不知道卡在哪一步、谁在等谁 |
| 人机协同弱 | 要确认时只能停在黑框或 IM，没有「同意 / 拒绝 / 改参数」 |
| 串场难 | 不同执行体输出格式不一，上下文没法在步骤间复用 |
| 难复盘 | 一次任务的决策、消息、产物链断裂 |
| 终端跳出去 | 一进交互式 CLI，工作台就变成旁观者 |
| 文档七零八落 | 群报告、节点台账在会话目录里，要靠文件管理器翻 |

平台要做的不是再发明一个编排器，而是给这些已经存在的能力一个**共同的群聊外壳**：看见流程、关键点闸门、任务可归档可续，数据还能给人读。

### 3. 应用场景：克隆群模板就能改

日常流水线收成一条群聊：每一步是脚本、CLI、TUI 或 Agent 成员，关键处加人闸门。仓库里常见配法如下。

**前端开发流**  
切分支 → 起本地服务 → 脚本截 Figma / 对照稿 → 导出或拉取接口文档 → 改页面 → 跑单测或 e2e → 提交并开/合 PR。本地服务和 TUI 走内嵌终端；合代码前用「同意」闸门。

**接口联调流**  
拉最新 OpenAPI / 导出接口文档 → 起 mock 或连测试环境 → 跑集成脚本 → 人眼对一下响应 → 改客户端 → 提交。文档和命令做成脚本成员，对不上就停在闸门。

**发版验收流**  
切发布分支 → 跑测试与打包 → 预览包 / 打开产物 → 人验收截图或清单 → 打 tag、合并主干。打包用本机命令；「能不能发」留给最后一步人工同意。

**本机排障 + 熔炉**  
复现命令进终端卡 → 需要改代码时点桌宠开熔炉（Grok）→ 人确认补丁 → 回归脚本 → 提交。熔炉和脚本同一条群聊里插队，不用另开窗口记进度。

面向用户是**个人开发者和小团队**：会配脚本、会开终端、需要 AI 插手但必须自己拍板的人。Windows / macOS / Linux 均可；解压运行包或 `npm install` 后本机打开 `127.0.0.1:5173`。

### 4. AI 用在哪一层，用了哪些工具

这不是「用大模型写一段文案」的案例，而是把 AI **嵌进可审计的流程**。

| 层级 | 在本项目里的含义 | 现状 |
|------|------------------|------|
| L1 辅助生成 | 快捷指令、群报告汇总、文档中心检索 | 有，但是壳 |
| L2 代理执行 | 熔炉 Grok：主持群聊、成员/节点适配、可选闸门审核 | **已落地**（3.x） |
| **L3 流程嵌入** | 群模板线性节点 + 人工闸门 + 场外 `@` 插队 + 台账 | **主战场** |
| L4 全自治 | 无人值守跑完整业务、自己合 PR | **明确不做** |

熔炉的技术选择很克制：

- **没有**自研 Grok HTTP 客户端；工作台是官方 `grok` CLI 的 PTY 宿主。
- 开炉写入短 `AGENTS.md` + `.grok/rules/session.md`，长文在 `ACTIVE.md`，禁止复述。角色壳一次只装一套：主持 / 成员适配 / 节点适配 / 审核，上下文不混装。
- JSONL Adapter 把可信侧通道里的 `question` 转成对话闸门，`result` 写回节点与群报告；解析失败降级为真实终端，不杀 PTY。
- 桌宠不是装饰：闲置 / 干活 / 等人三态；未装或未登录 Grok 时点开弹出 Build 教程，而不是静默失败。

<img src="./assets/screenshots/furnace-workspace-chat.webp" alt="熔炉铺满 GUI：欢迎卡、桌宠头像、底部输入" width="100%" />

<p align="center"><sub>熔炉默认铺满 GUI，可切回官方 TUI，可缩小回三栏；返回群聊只关这层皮，进程还在。</sub></p>

脚本成员则是另一类「智能」：BAT / PowerShell / 任意 CLI，默认走内嵌终端（node-pty + xterm.js），交互式工具不必跳出去。

### 5. 当前覆盖范围（4.2.0 能干什么）

| 能力 | 一句话 |
|------|--------|
| 群聊式工作流 | 群模板、成员、会话、线性节点与实时状态 |
| 人工闸门 | 启动确认、参数输入、同意/拒绝；最后一步「同意并完成」即归档 |
| 熔炉 | 桌宠入口；GUI/TUI 同一条 grok；短合同开炉；GUI 附件把路径写入同一进程 |
| 内嵌 TUI | 真实 PTY：输入、ANSI、resize、回放、停止、满屏与全屏 |
| 流程轨 | 当前节点、历史、克隆、跳过折叠、从节点继续；适配角标 |
| 场外协助 | `@成员` 临时插队，完成后回主线 |
| 快捷输入 | `/` 指令、`@` 协助、`#` 会话参数与节点输出 |
| 群报告 | 自动汇总参数、节点 I/O 和人工备注，落地 Markdown |
| 文档中心 | `/docs` 新标签聚合群报告/台账；全文搜索；按群导出 zip |
| 更新与备份 | 启动检查更新（默认可关）；关于页一键备份与恢复；更新永不碰数据目录 |
| 本地数据 | SQLite 是调度真相；Markdown 给人读；附件和日志在本机文件 |

**明确边界**：线性流程，不做复杂 BPMN / 并行网关；本机 Web，桌面壳后置；熔炉暂定只接 Grok；不做云端同步。

### 6. 怎么用、用多勤

设计上的节奏是**按任务开聊，而不是 7×24 挂着一个 Bot**：

1. 克隆或选一个群模板（内置「演示流」可一键开聊）。
2. 过启动闸门，按空格/换行提交项目参数（同会话 `#1` `#2`… 递增追加）。
3. 成员跑脚本或打开内嵌终端；人在审核闸门点同意或拒绝。
4. 中途可以 `@` 另一个成员插队，跑完回到主流程。
5. 最后一步「同意并完成」：群聊归档并释放本会话进程；再发消息 = 解档，仍在同一会话。
6. 需要改代码时点桌宠开熔炉；用完缩小回三栏，进度还在右边。

`docs/demo.md` 把主路径标成 **约 2 分钟**。开发者每个交付日可以开多条会话（同模板同目录允许并行）；熔炉按需点火。因为数据不出本机，案例库里不应填写「日活 / 周活」——那不是这个产品会收集的数字。

### 7. 量化提效：能数的数，和不该编的数

**产品路径（可复现）**

- 演示流：确认开始 → 提交参数 → 回声成员 → 审核 → 内嵌终端命令 → 再同意 → 看流程轨与群报告 → **同意并完成**。文档约定约 2 分钟闭环。
- 参数与节点入出自动进群报告 `ANNOUNCEMENT.md` 和节点台账 `step-*.md`，复盘不再靠翻聊天记录。
- 最后一步必须人点「同意并完成」，发版/合码类流程把「能不能过」从口头确认收成一次可审计的闸门。
- `@` 插队与「从这里继续」（前进跳或追加克隆）让人不必为一次例外拆一条新流水线。

**工程度量（仓库可核对）**

| 指标 | 数字 | 含义 |
|------|------|------|
| 演示闭环 | ~2 分钟 / 8 步 | 主路径可讲、可录 |
| 引擎拆分 | 4090 行 → 46 行门面 + 9 个单向模块 | 闸门与推进可直测 |
| 工作台拆分 | 5657 行 → 799 行布局壳 | 三栏组件化，状态单一来源 |
| 自测 | 服务端 139 例 + 前端纯逻辑 23 例 | CI：Lint → Test → Build → 打包冒烟 |
| 发布跨度 | 2026-07-17 `0.1.0` → 2026-09-02 `4.2.0` | 约 7 周、四个大版本封板 |
| 提交 | 486 | 含三平台运行包 |
| 平台 | Windows / macOS / Linux | 解压即用，需 Node 18+ |

没有「节省 80% 人天」这类无法从仓库验证的业务百分比。若对外投稿需要 ROI，建议用真实团队的一条流水线（例如发版验收）做前后对照：切窗口次数、复盘写报告时间、误发次数，而不是套用上文工程数字。

### 8. 未来规划

已写在 README 路线图、仍未做的部分：

- **桌面形态**：托盘独立窗、系统通知、开机驻留（Web 内核套壳，不另写引擎）。
- **终端治理**：多终端标签、更多 CLI Adapter（JSONL 契约已在 2.4 封板）。
- **更新**：4.2.0 只做检查 + 获取 + 备份恢复；**4.3+** 再考虑自动下载替换（self-replace）。
- **文档**：版本历史 / diff、git 化台账另案；代码高亮按需评估。

坚持不做的：云端多租户、把某一家 IDE Agent 替换掉、花哨画布式 BPMN、把业务示例写死成唯一产品方向。

### 9. 一句话收束

把已经存在的脚本、终端和 Grok，收进同一条**看得见、拦得住、留得下**的群聊。节点是锚点，人是活水——这就是 `oh-my-co-work` 作为人机协同案例要讲的事。
