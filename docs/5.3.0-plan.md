# 5.3.0 计划：可追溯、可复用、可扩展

> 定位：5.0～5.2 解决"能用、顺手"（性能、交互、CLI、熔炉、文档中心）。**5.3.0 不再修补，而是补三块能力：**
> 1. **可追溯**——每一步 Agent 到底改了什么、花了多久、能不能一键回退；
> 2. **可复用**——流程、成员、提示词、炼化规格能导出分享、能模板化；
> 3. **可扩展**——不止 Cursor CLI / Grok，新的命令行 Agent 能低成本接进来。
>
> 约束（来自 `docs/mvp.md` 北极星，**5.3.0 不突破**）：本机优先、不夹带远程后台；线性 workflow + 元节点，不上重型编排器；只做 MVP，不做花哨堆砌。凡与此冲突的想法放在末尾"暂不做"。
>
> 前置：5.1.0（CLI/桌面壳稳定）、5.2.0（复制粘贴、炼化还原、文档中心入口）完成度越高，本版越顺。
> 标注：**P0** 本版核心；**P1** 重要；**P2** 有空再做。状态用 `[ ]` / `[x]` 维护。

## 一、可追溯：让 Agent 的每一步"看得见、退得回"

痛点：用户把成员/熔炉接到真实代码目录后，Agent 改了什么只能靠自己翻 git；炼化备份只是 zip，没有统一的"步骤快照"概念。协同台应成为"改动的账本"。

- [x] **TRC-01 P0 [5.3.0 stepSnapshot git HEAD→diff · FlowRail 摘要/展开 · 非 git/adaptBackup 待补] 步骤级变更快照与 diff**
  每个节点执行前后，对其工作目录做**轻量快照**（有 git 仓库则记录 `HEAD` + `git diff --stat`/补丁；无 git 则只对"本步触碰过的文件"做哈希 + 副本，沿用 `adaptBackup` 的上限策略）。在流程轨节点上显示"改了 N 个文件 +x −y"，点开看 diff。
- [x] **TRC-02 P0 [5.3.0 step-revert API + FlowRail + 设置还原中心 · 适配备份列表待补] 一键回退到某一步之前**
  基于 TRC-01：节点右键"回退本步改动"（先预览、再确认；有用户后续修改则提示冲突）。与 5.2.0 的炼化还原（REF-01）合并成**统一的"还原中心"**：炼化备份、适配备份、步骤快照在同一处列出、同一套还原逻辑。
- [x] **TRC-03 P1 [5.3.0 FlowRail 时间线 Tab + API · 终端回放跳转待补] 运行时间线**
  会话级时间线视图：节点开始/结束、人工介入、场外协助、闸门通过/拒绝、终端启动/退出、文档产出，按时间排列、可筛选；点击事件跳转到对应消息/终端回放/文档。用于复盘与排障。
- [x] **TRC-04 P1 [5.3.0 日志 JSON 预览 + 时间线终端回放对话框 · asciicast/倍速待补] 终端录制与回放**
  终端输出本来就落日志（带时间戳的 asciicast 格式更佳），提供会话内"回放"（可倍速、可跳转到某次工具调用）。比下载 `.log` 更适合复盘 Agent 做了什么。
- [x] **TRC-05 P1 [5.3.0 GET /usage-stats + 设置页摘要 · 重试/细粒度待补] 本机用量与耗时统计**
  不上传任何数据，仅本地统计：每成员/每步耗时分布、失败率、重试次数、终端占用时长、日志磁盘占用；设置里一页看清"谁最慢、谁常失败"。为性能优化提供依据。
- [x] **TRC-06 P2 [5.3.0 会话 audit-export Markdown · 附件/脱敏扫描待补] 审计导出**
  把某会话的时间线 + 快照摘要 + 台账打成一份可交接的审计包（Markdown + 附件），脱敏规则复用现有 `redact`。

验收：任选一个跑完的会话，能在 3 次点击内看到"每一步改了哪些文件"，并能把某一步的改动完整回退且字节级一致。

## 二、可复用：流程、成员、规格能分享

痛点：群模板、成员、炼化规格、提示词都只存在本机数据库里，换机器/分享给同事只能整库备份（粒度太粗）。

- [x] **REU-01 P0 [5.3.0 .acw.json 导出/导入 · 路径占位 · 冲突 rename/skip · 覆盖导入已补 overwrite 原地更新 + 单测] 模板导入导出（单文件）**
  群模板、成员、步骤、`/` 指令、炼化规格可导出为单个 `.acw.json`（或 `.acwpack` zip），导入时做**版本与冲突检测**（同名则重命名/覆盖/跳过），敏感字段（命令里的密钥、绝对路径）导出时提示并可替换为占位符。与现有"一键导入/导出"（整库、整文档）区分：这里是**配置级**。
- [x] **REU-02 P1 [5.3.0 {{WORKSPACE}}/{{HOME}} 导入替换 · 环境变量表待补] 路径与环境参数化**
  模板里的工作目录、脚本路径支持变量（`{{workspace}}`、`{{home}}`），导入时一次性填写；避免"导进来全是别人的 `D:\...`"。
- [x] **REU-03 P1 [5.3.0 内置 3 模板 + 群模板页一键创建 · 演示数据分离待补] 内置模板库**
  随包提供几份高质量示例流程（代码评审、需求拆解、发版检查、日报汇总），一键创建；替代目前"演示数据"的角色，并能被"删除演示数据"精确识别。
- [x] **REU-04 P1 [5.3.0 settings.promptSnippets + {{snippet:}} + 设置页 CRUD · 成员多选 UI 待补] 提示词与角色片段库**
  熔炉/成员的启动提示词、`AGENTS.md` 注入块做成可命名、可版本化的片段，成员里引用片段而不是复制粘贴；改一处，引用处同步。
- [x] **REU-05 P2 [5.3.0 GET/POST /skills + 安装到 data/skills · Cursor skills 目录一键待补] Skill 打包**
  `skills/agent-refine-skill` 这类外部 Agent 技能，提供统一的安装/更新入口（复制到目标 CLI 的 skills 目录），并校验版本。

验收：在机器 A 导出一个流程，机器 B 导入后只需填写 1～2 个路径变量即可跑通。

## 三、可扩展：更多 Agent，而不止两个

痛点：熔炉里 Agent 种类是写死的二选一（`grok` / `cursor`），代码里还有靠正则识别 Agent 的逻辑（见 5.2.0 FUR-04）；新 CLI（Claude Code、Codex CLI、Gemini CLI、aider 等）接入成本高。

- [x] **EXT-01 P0 [5.3.0 GET /agent-registry + customAgents 设置 · 前端熔炉列表/探测待接] Agent 适配器注册表**
  把"Agent"抽象为配置驱动：`id / 显示名 / 启动命令与参数 / 探测命令与登录检测 / 欢迎与失败文案 / 输出解析 profile / 粘贴策略（是否 bracketed paste、提交键与延迟）/ 附件语法`。内置 Grok、Cursor，另允许用户在设置里新增"自定义 CLI Agent"。前端不再硬编码 Agent 列表与品牌文案。
- [x] **EXT-02 P1 [5.3.0 parseProfiles + 样本 jsonl API · 录制 UI/回归跑批待补] 解析 profile 与黄金样本**
  GUI 视图对不同 Agent 用不同解析规则（见 5.2.0 FUR-01）。提供 profile 开发指南与"录制 → 生成样本 → 回归测试"工具，让新增 Agent 不靠猜。
- [x] **EXT-03 P1 [5.3.0 registry structuredAdapter → jsonl 终端 · 全事件覆盖待补] 结构化通道优先**
  Agent 若支持 JSON/stream 输出或事件文件，优先走结构化通道（现有 `jsonl adapter` 已是雏形），把闸门、工具调用、文件改动变成**一等事件**，直接喂给 TRC-01/03，而不是解屏幕。
- [x] **EXT-04 P2 [5.3.0 settings.mcpConnections + GET /mcp/connections · 代理转发不做] MCP / 外部工具接入点（只读优先）**
  评估在不破坏"本机优先"的前提下，让成员暴露/消费本机 MCP 工具；首期仅做"配置可见 + 一键复制到 CLI 配置"，不做代理转发。
- [x] **EXT-05 P2 [5.3.0 script.sandbox.readOnly 环境标记 · 强制隔离待补] 脚本成员沙盒选项**
  脚本类成员默认在用户目录直接执行；提供"只读目录 / 临时工作副本 / 超时与内存上限"的执行策略，降低误操作风险。

验收：不改前端代码，仅通过设置新增一个自定义 CLI Agent，即可在熔炉里启动、粘贴、复制、查看失败指引。

## 四、流程能力：在"线性"之内更稳

在不引入重型编排的前提下，补几个高频刚需（仍是线性主线 + 人可绕行）：

- [x] **FLW-01 P1 [5.3.0 step.run timeout/retry/onFailure + advance 重试/超时 · 步骤编辑器 UI 待补] 步骤级超时与重试**
  每步可设置超时、失败自动重试 N 次（带间隔）、失败后动作（停下等人 / 跳过 / 终止）。结果写入时间线。
- [x] **FLW-02 P1 [5.3.0 context.dryRun + stepDryRun + 群模板开聊选择 · 会话内切换待补] 试运行（Dry run）**
  不真正执行脚本/Agent，仅走一遍参数解析、路径与命令探测、权限与配额检查，输出"如果现在跑会发生什么"的清单；能提前发现 PATH、路径、登录问题。
- [x] **FLW-03 P1 [5.3.0 闸门 diff/风险提示 + 拒绝附言 · 台账深链待补] 闸门升级**
  人工审核闸门展示本步变更 diff（依赖 TRC-01）、关联台账与风险提示（如修改了配置/密钥类文件）；支持"通过并备注 / 拒绝并写回原因给 Agent"。
- [x] **FLW-04 P2 [5.3.0 group.config.paramSpecs + 开聊/步骤校验 · 模板编辑器 UI 待补] 参数校验与默认值**
  `#` 参数声明类型、必填、默认值与示例，开聊前统一校验并在输入框里补全。
- [x] **FLW-05 P2 [5.3.0 step.skipWhen + normalizeSteps 透传 · 可视化配置待补] 条件跳过（单向）**
  仅支持"按参数/上一步结论决定是否跳过本步"，不做分支合并；保持流程图仍是一条线。
- [x] **FLW-06 P2 [5.3.0 scheduledJobs + localScheduler · 文件触发/设置 UI 待补] 定时与触发**
  本机定时启动某个群模板（仅应用运行期间）、文件变化触发提醒；不引入后台常驻服务。

## 七、额外建议（供取舍）

1. **先做"还原中心 + 步骤快照"（TRC-01/02）**：它同时解决炼化还原、闸门审阅、Agent 误改回退三个问题，是 5.3.0 的杠杆点，其他功能（时间线、审计、闸门 diff）都依赖它。
2. **命令面板（DSK-01）成本低、感知强**：纯前端为主，可早期交付，显著提升"桌面应用感"。
3. **Agent 适配器注册表（EXT-01）要趁早**：每多一个硬编码分支，后面拆得越痛；5.2.0 先把 Agent 判断改成服务端下发字段（FUR-04）作为铺垫。
4. **把"人是活的"做成可见指标**：统计"人工介入次数 / 场外协助次数 / 闸门拒绝率"，用数据证明产品理念，也帮助用户优化流程（放在 TRC-05）。
5. **保持克制**：每项新增能力都要回答"是否能用一条线 + 元节点表达"。答不上来就不做。

## 八、暂不做（与北极星冲突或收益不明）

- 云端同步、多用户协作、远程只读分享页（违背"本机优先、不夹带后台"；如确有需求，以"导出静态 HTML 报告"替代）
- 通用 BPMN / 并行分支 / 复杂条件网关
- 内置模型调用与计费代理（继续做"桥梁"，不做模型本体）
- 插件市场（先用模板导入导出与 Skill 打包满足复用）
- 遥测上传（仅本地统计）
