# oh-my-co-work 2.x · 内嵌 TUI 实施计划

| 属性 | 内容 |
|------|------|
| 目标版本 | `2.x` |
| 状态 | **`2.4.0`**（终端偏好、配额脱敏、JSONL Adapter）；`2.3.0` 资源释放已封 |
| 更新日期 | 2026-08-17 |
| 设计文档 | [tui-2x.md](./tui-2x.md) |

## 1. 实施原则

1. 先建立真实 PTY 与进程治理，再做业务语义融合。
2. 保留现有 pipe/detached 路径，逐个工具迁移，不一次性替换所有 runner。
3. 终端字符流和结构化业务事件分离。
4. 每个阶段都必须可独立回退到当前脚本执行方式。
5. Windows、Linux、macOS 分别构建；原生依赖不可假设跨平台兼容。
6. 安全校验、资源上限和进程回收必须与首个可交互版本同时交付。

## 2. 版本切分

| 版本 | 主题 | 交付边界 |
|------|------|----------|
| `2.0` | 可观看的真实终端 | PTY、xterm、终端卡、实时输出、resize、停止、日志；默认只读 |
| `2.1` | 可交互终端 | 键盘输入、粘贴保护、焦点管理、刷新重连、设置页 |
| `2.2` | 工作流融合 | 节点生命周期、结构化 adapter、提问转闸门、结果写回 |
| `2.3` | 稳定与扩展 | 多终端、性能治理、更多 adapter、恢复能力和完整三平台封板 |

版本号表示功能边界，不要求所有目标工具在 `2.0` 一次完成适配。

### 2.1 当前落地（2.0.0 / 2.0.1）

已交付：真实 PTY、xterm 延迟加载、终端消息卡、中栏交互工作区、键盘输入、resize、有限回放、刷新重新附着、日志、停止与会话进程回收；成员设置可在普通执行和内嵌终端间选择。

`2.0.1` 加固：回环 Origin + 随机本机令牌（REST/WebSocket）；停止成功只认真实退出码；注销时清理 PID；日志异步写入并设 10 MiB 上限；attach 先 flush pending；前端按 seq 写入、WebSocket 断线重连、REST 不覆盖更新流。

后续重点：终端元数据持久化、可信 JSONL Adapter、提问转闸门、多终端治理、配额/脱敏设置和完整三平台自动化矩阵。

## 3. Phase 0：技术验证

### 目标

在不接入正式工作流的隔离原型中验证核心风险。

### 任务

- [ ] 引入最新稳定版 `node-pty` 和 `xterm.js`。
- [ ] 创建最小 PTY 服务，运行：
  - Windows：BAT、PowerShell、一个全屏 TUI。
  - Linux/macOS：Shell、REPL、一个全屏 TUI。
- [ ] 验证 ANSI 色彩、光标移动、清屏、Unicode、中文输入。
- [ ] 验证 resize、Ctrl+C、退出码和进程树清理。
- [ ] 验证 `node-pty` 在当前运行包中的原生模块打包。
- [ ] 测量持续大输出的 CPU、内存和 WebSocket 帧数量。
- [ ] 列出会强制打开独立窗口的脚本，确认其迁移方式。

### 退出标准

- 三个平台至少各完成一次原生构建和基础运行验证。
- 目标 TUI 不出现明显错位、乱码或无法退出。
- 明确 Node ABI、Windows 版本和打包约束。
- 若 `node-pty` 无法满足目标平台，必须在进入正式开发前重新评估技术方案。

## 4. Phase 1：2.0 可观看终端

### 4.1 服务端

- [ ] 新建 `server/src/terminal/` 模块边界。
- [ ] 实现 `TerminalSessionService`：
  - create
  - attach
  - resize
  - kill
  - list/get
  - exit cleanup
- [ ] 在 `runners.js` 增加 `executionMode`，保持 pipe/detached 行为不变。
- [ ] 在 `processRegistry.js` 登记 terminalId、runId、成员、节点和 PID。
- [ ] 增加终端 WebSocket 消息路由。
- [ ] 实现输出批处理、序列号、环形缓冲和磁盘追加日志。
- [ ] 增加命令来源、cwd 和消息大小校验。
- [ ] 增加终端元数据迁移及查询 API。

### 4.2 前端

- [ ] 新建 `TerminalView.vue`，只封装 xterm 生命周期。
- [ ] 新建 `TerminalSessionCard.vue`，显示最近输出和状态。
- [ ] 新建 `TerminalWorkspace.vue`，支持进入/返回、resize 和停止。
- [ ] 在 `Workbench.vue` 接入终端卡与中栏模式切换。
- [ ] 页面只读预览限频，避免每个输出块重渲染消息列表。
- [ ] 加入项目深色终端主题和基础可访问性标签。

### 4.3 2.0 暂不做

- 不开放用户键盘输入。
- 不做结构化对话解析。
- 不做服务重启后重新接管 PTY。
- 不做多个终端标签页。

### 4.4 验收

- [ ] 从成员脚本启动 terminal 模式，聊天出现终端卡。
- [ ] 点击可进入完整终端并正确自适应尺寸。
- [ ] 返回聊天后进程继续，卡片状态持续更新。
- [ ] 可停止终端，流程得到明确的 killed/exit 结果。
- [ ] 日志可查看和下载，消息表中不保存完整大输出。
- [ ] 归档会话后终端及子进程全部结束。

## 5. Phase 2：2.1 可交互终端

### 5.1 输入协议

- [ ] 实现 `terminal.input`，校验连接、会话和 terminalId。
- [ ] 支持 Enter、Tab、方向键、Ctrl+C 和常见功能键。
- [ ] 限制单帧输入大小及发送频率。
- [ ] 增加多行粘贴确认。
- [ ] 对可信工具提供可配置的粘贴策略。

### 5.2 焦点与体验

- [ ] 终端获得焦点时显示明确状态。
- [ ] `Esc` 或工具栏按钮退出终端焦点。
- [ ] 处理聊天快捷键与终端快捷键冲突。
- [ ] 支持复制、选区、搜索、清屏和日志入口。
- [ ] 增加主题、字体、字号、行高、光标和回放设置。
- [ ] 终端退出后按设置自动收起。

### 5.3 重连

- [ ] 页面刷新后查询运行中的终端。
- [ ] attach 时先发送有限快照/缓冲，再接实时序列。
- [ ] 检测序列缺口并提示“部分输出未回放”。
- [ ] WebSocket 断开期间 PTY 继续运行，重连后恢复。

### 5.4 验收

- [ ] 典型菜单式 TUI 可仅用键盘完成一次完整任务。
- [ ] 聊天输入与终端输入不会串线。
- [ ] 多行粘贴不会无提示执行。
- [ ] 刷新页面后可重新进入仍在运行的终端。
- [ ] 终端连接中断不会阻塞工具或无限堆积内存。

## 6. Phase 3：2.2 工作流融合

### 6.1 节点生命周期

- [ ] 为节点结果增加 terminalId、exitCode、logPath 和 summary。
- [ ] 定义 terminal running、等待输入、退出、失败、被杀与中断的节点映射。
- [ ] 正常退出后按成员配置决定自动推进或进入闸门。
- [ ] 非零退出、信号退出和用户停止使用不同结果语义。
- [ ] “从这里继续”及成员切换时处理旧终端。

### 6.2 Adapter 框架

- [ ] 定义 adapter 接口和可信事件 schema。
- [ ] 实现通用 JSONL adapter。
- [ ] 将 `message` 事件写入对话。
- [ ] 将 `question` 事件转换成现有闸门。
- [ ] 将 `tool.start/end` 显示为工具调用卡。
- [ ] 将 `result` 写入节点 output 和群报告。
- [ ] adapter 失败时降级为 L0 真实终端，不中断 PTY。

### 6.3 首批工具

实施前选择少量代表工具：

- 一个纯 BAT/PowerShell 菜单工具，用于 L0。
- 一个能输出结构化事件的 CLI，用于 L2。
- 一个全屏重绘 TUI，用于终端兼容验证。

每个 adapter 单独维护版本兼容说明，不能把工具输出格式散落在工作台组件中。

### 6.4 验收

- [ ] TUI 内的结构化提问可在主对话中审批并回传。
- [ ] 工具调用与结果可形成可复盘的聊天记录。
- [ ] 节点输出、群报告和终端日志之间有稳定引用。
- [ ] adapter 升级失败时不影响用户直接使用终端。

## 8. 数据库与兼容迁移

### 8.1 数据迁移

- [ ] 新增 `terminal_sessions`，迁移必须可重复执行。
- [ ] 旧会话和旧节点无需补造终端记录。
- [ ] 删除终端记录时明确日志文件是否一并删除。
- [ ] 备份和恢复流程纳入终端元数据与日志目录。

### 8.2 配置迁移

- 未设置 `executionMode` 的脚本成员默认走内嵌终端；显式 `pipe` 才用普通执行。
- 原 `showConsole: true` 不直接等同 terminal；提供明确迁移提示。
- `detach: true` 保持独立窗口语义，除非用户主动改为 terminal。
- 设置保存时校验 terminal 配置，不支持的平台给出可理解提示。

### 8.3 回退

- 每个成员可从 terminal 切回 pipe/detached。
- PTY 启动失败时不应自动执行另一条未经确认的命令。
- 可提供管理员级全局开关，暂时禁用内嵌终端。

## 10. 性能与资源门槛

正式实现时通过基准测试确定数值，至少约束：

- 单终端内存环形缓冲上限。
- 单终端日志文件上限与滚动数量。
- 单个 WebSocket 输出批次大小和刷新频率。
- 单会话并发终端上限。
- 单帧输入和输出上限。
- attach 回放上限。

不得让终端完整输出进入 Vue 响应式消息数组，也不得在内存中无限拼接 Buffer。

## 11. 安全检查表

- [ ] 浏览器不能提交任意 shell/command。
- [ ] terminalId 不能跨会话操作。
- [ ] cwd 完成规范化和允许目录校验。
- [ ] 输入、输出、resize 均有限流和大小限制。
- [ ] 多行粘贴有确认。
- [ ] 环境变量按白名单传入。
- [ ] API、日志和错误不返回 Token。
- [ ] Adapter 控制事件来自可信通道并严格校验。
- [ ] kill 能结束完整进程树。
- [ ] 归档、删除和备份符合日志保留策略。

## 12. 风险与应对

| 风险 | 应对 |
|------|------|
| `node-pty` 原生模块打包失败 | Phase 0 先验证三平台；CI 各平台原生构建 |
| Windows 脚本强制弹新窗口 | 标记 incompatible；改包装脚本以前台模式运行 |
| 高频输出拖慢页面 | 服务端批处理 + 前端限频 + 环形缓冲 |
| 终端输出被误当业务事件 | PTY 与可信结构化事件分通道 |
| 进程树残留 | 增强 processRegistry；集成测试归档、停止和异常退出 |
| 中文乱码 | 明确 UTF-8、代码页、locale；三平台用例覆盖 |
| 快捷键与聊天冲突 | 显式焦点模式和按键白名单 |
| 日志泄密 | 环境变量白名单、脱敏、配额、清理和删除能力 |
| 工具升级破坏 adapter | adapter 版本隔离；失败降级到 L0 |

## 14. 2.x 最终完成定义

只有同时满足以下条件，2.x 才可封板：

- 三个平台运行包均能启动并运行至少一个真实交互式 TUI。
- pipe、terminal、detached 三种模式边界清晰且兼容旧配置。
- 对话终端卡、完整工作区、输入、resize、重连和停止均通过验收。
- 归档、续跑、切换成员和服务异常场景无已知进程泄漏。
- 日志、配额、脱敏、权限和 cwd 校验完整。
- 至少一个 L2 adapter 完成提问、工具调用和结果融合。
- 自动化测试覆盖核心协议、生命周期和安全校验。
- 用户文档、脚本迁移指南和三平台排障说明齐备。
