## 1. 一句话

**熔炉**是 3.x 产品名，也是现有 **统一管理员** 的继任：一个 **Grok Agent**（无内置工具），形象是黑裙美少女精灵。适配靠提示词。UI 上不是按钮，就是这只精灵。**Adapter（JSONL）仍是融合契约。**

工作台仍是 oh-my-co-work（群聊 + TUI）。熔炉先做极简 Agent：可先跑 **本机 Grok TUI**，再拓展成 Grok 客户端 / 桌面精灵。用户爱用精灵还是工作台，优胜劣汰，不为挽留工作台加复杂交互。

## 2. 和 2.x 怎么接

| 层 | 是什么 | 谁负责 |
|----|--------|--------|
| PTY / 终端守护者 | 工具在工作台里像真实终端一样活着 | 2.x，继续保留 |

| 熔炉 | 原「统一管理员」的产品替换：Grok Agent + 精灵形象；提示词适配；审核仍走闸门（另一套上下文） | 3.x |

判定有没有跑偏：

> 关掉熔炉，改过的成员、带标记的适配步骤还能不能当普通流程跑。能，就是工作台。

## 3. 熔炉出现在哪（已决）

熔炉 = Grok Agent + 适配提示词 + 黑裙精灵形象。**不是工具箱，不是单独一颗「适配按钮」。** 加人 / 加步骤处只有一个选项：**是否适配**（点精灵或勾选，hover 说明逻辑）。

### 3.0 精灵，不是按钮

入口是黑裙少女 Logo（闲置 / 工作 / 等人 三态卡通）。未配置 Grok 时 **不隐藏精灵**，正常展示，并提示下载 Grok Build（或当时官方客户端）并完成配置。可先接 **本机 Grok TUI**（走现有内嵌终端），再拓展为 Grok 客户端 / 桌面精灵。只做极简 Agent；工作台与精灵谁更常用交给用户习惯，不为挽留工作台加复杂交互。

### 3.1 是否适配（只有一个选项）

用户只决定开不开适配。内部顺序 **写死、hover 告诉用户**：

1. **优先改代码** 做适配（包装、JSONL、成员配置等）。  
2. **改不了代码** 再走 **适配节点**（步骤上打标记，见 §4）。

不要同时让用户选「改代码还是加节点」。改源文件前 **默认打压缩包备份**，尽量不影响其它场景使用；备份可恢复。

### 3.2 适配与审核不混（三套 prompt / 记忆）

适配是适配，审核是审核，主持是主持，上下文分开：熔炉可以做适配，闸门仍可配给人审或给熔炉审（原管理员通道的继任）。**角色壳一次只装一套；开聊另附情境包。**

| 作用 | 何时装入 | Prompt（进仓库） | 记忆种子（进仓库） | 本机记忆（不进 git） |
| --- | --- | --- | --- | --- |
| 群聊主持 | 开聊 / 尚未换到适配或审核 | `prompts/session.md` | `memory-seed/session.md` | `memory/session.md` |
| 成员适配 | 成员勾了适配、步骤未勾 | `server/config/furnace/prompts/member-adapt.md` | `memory-seed/member-adapt.md` | `data/furnace/memory/member-adapt.md` |
| 节点适配 | 步骤勾了适配 | `prompts/node-adapt.md` | `memory-seed/node-adapt.md` | `memory/node-adapt.md` |
| 系统审核 | 闸门要熔炉确认 | `prompts/review.md` | `memory-seed/review.md` | `memory/review.md` |

本轮装入写成 `data/furnace/ACTIVE.md`（Grok TUI 工作目录就是这里）。系统气泡只写「熔炉本轮：xxx」，不把全文灌进聊天。记忆种子只复制一次，已有本机记忆不覆盖。

开聊之后熔炉要的是 **节点地图**（哪个节点是什么、游标在哪），不是某一个业务场景的专用 prompt。角色壳回答「你是谁」；节点一览 + 当前节点合同回答「工作流里这一格是什么」。管理模型见 **[crucible-3.2.md](./crucible-3.2.md)**。

### 3.3 统一管理员 → 熔炉

现有 **统一管理员**（`unified_admin`、设置里的全局管理员、流转里的「管理员确认」、斜杠「请管理员协助」等）**产品层全部替换为熔炉**。内部字段名（`admin`、`unified_admin`）迁移期可保留，对用户只见熔炉。模型提供方 **暂定只 Grok，不换**，以后再议。

### 3.4 建群 / 闸门

建群仍可请熔炉协助。闸门执行者可配人（默认）或熔炉。对用户文案不再出现「管理员」，改称熔炉。

## 4. 适配怎么落地（已决）

| 项 | 已决 |
|----|------|
| 用户选项 | 仅「是否适配」；顺序见 hover |
| 优先 | 改代码 |
| 回落 | 适配节点：步骤 **标记**，**不新开 `step_type`** |
| 备份 | 改源文件前默认压缩包 |
| 会话 | **正常是什么展示什么**；标记不改气泡种类 |
| 流程轨 | 适配步骤加 **Tab / 标识**，方便认出来 |
| JSONL | 能接到现有契约就写侧通道 |

「改不了代码」的判定（只读、二进制、Grok 失败、目录策略）实现时再列。产品口径：能改就改，不能再打适配标记。

## 5. 形态：极简精灵（先 Grok TUI，再客户端）

### 5.1 已决

熔炉 **就是桌面精灵**（黑裙少女），不是工具栏按钮。产品名熔炉。可切换回工作台 TUI，但不为「必须切回工作台」加戏。

落地顺序：

1. 本机 **Grok TUI**（现有内嵌终端里跑 Grok）  
2. 再拓展 **Grok 客户端 / 托盘精灵**

未配置时精灵仍在，提示下载并配置 Grok Build。

### 5.2 和主题

群聊工作台仍是账本；熔炉是管理员继任 + 适配 Agent。用户习惯优胜劣汰。精灵与工作台仍应共用本机 server、会话、成员、闸门、终端，避免两套账。

### 5.3 形象 Logo（已决）

不替代工作台 [人·文档·机](./brand-logo.md)。卡通 **黑裙美少女**，尽量极简、有感染力。

**三态**（均为卡通 Logo，可为静态帧）：

| 态 | 何时 |
|----|------|
| **闲置** | 待命、未接任务 |
| **工作** | 正在适配 / Grok 推理 / 改代码 |
| **等人** | 闸门等人、待配置 Grok、待用户点 |

禁止工作态挂一身工具图标。发型脸型后细化。

### 5.4 风险（仍有效）

| 风险 | 说明 | 已决应对 |
|------|------|----------|
| 厂商 | 暂定只 Grok，不换 | 以后再议；内部仍避免把协议写死在引擎到处 |
| 改源文件 | 破坏其它用法 | 改前默认压缩包备份 |
| 管理员文案 | 与熔炉并存会乱 | 产品层全部改称熔炉 |
| 双形态 | 精灵赢走工作台 | 接受；只做极简 Agent |

## 6. 非目标（3.x 也不做或明确后置）

- 用熔炉替换 JSONL 契约，或解析终端画面充当 Adapter。  
- **在熔炉内做工具箱 / 插件市场**。  
- 给人两个适配入口（改代码 vs 加节点）让用户自选。  
- 未配置 Grok 时隐藏精灵。  
- 为适配节点新增聊天消息 `step_type` / 气泡种类（只用标记 + 流程轨 Tab）。  
- 多人同时控制同一 PTY。  
- 条件分支 / 并行画布（不因熔炉提前做）。  
- 纯云端托管工作台。

## 7. 名词

| 词 | 含义 |
|----|------|
| Adapter | 融合**契约**：可信 JSONL 侧通道。门。 |
| 熔炉 | 原统一管理员的继任；Grok Agent；黑裙精灵（闲置/工作/等人）；无内置工具。 |
| 是否适配 | 唯一用户选项；hover：优先改代码，改不了再标记适配节点。 |
| 适配标记 | 打在步骤上，非新 `step_type`；会话按原类型展示。 |
| 流程轨 Tab | 标出带适配标记的步骤，便于在流程图里找。 |
| 终端守护者 / 工作台 | oh-my-co-work 三栏 + 内嵌 TUI；与熔炉桌面可切换。 |
| Grok / Grok Build | 熔炉所用的 Agent 模型与编码/构建来源；对接方式后细化。 |

## 8. 开放问题（还没拍）

- 「改不了代码」：只读、二进制、过大、找不到源文件、备份失败 → 不改文件，只打步骤标记。  
- 压缩包：`data/backups/adapt/<成员id>/adapt-<时间>.zip` + 同名 json 清单；只含即将改动的文件。  
- 流程轨：步骤角标「适配」+ 右侧「适配」筛选 Tab（不是新页面）。  
- 三套上下文：prompt 进仓库、记忆在 `data/furnace`、本轮只写 `ACTIVE.md`。  
- `unified_admin` 的内部 id 是否保留、只改展示名？  
- 精灵点开时是否切换角色。  

发型、正侧脸、动画仍后细化。
