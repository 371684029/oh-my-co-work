## 1. 一句话

**熔炉**是 3.x 的产品名：一个 **Grok Agent**（工作台里可配到加人 / 建群 / 闸门；桌面上随叫随到）。**熔炉里面没有工具。** 适配靠提示词驱动 Grok，不靠内置工具箱。**Adapter（JSONL）仍是融合契约，不是熔炉本身。**

工作台（oh-my-co-work）主题不变：Workflow = 群聊，工具 = 成员，关键处可配人闸门，终端仍是执行载体。桌面入口对外就叫熔炉。

---

## 2. 和 2.x 怎么接

| 层 | 是什么 | 谁负责 |
|----|--------|--------|
| PTY / 终端守护者 | 工具在工作台里像真实终端一样活着 | 2.x，继续保留 |
| JSONL Adapter | 子工具往侧通道写事件，进入对话、闸门、节点、群报告 | 2.x 契约，3.x **不改门、只帮工具走进门** |
| 熔炉 | 一个 Grok Agent：提示词驱动适配；加人改代码，或加节点时插入适配节点 | 3.x |

判定有没有跑偏：

> 关掉熔炉，它改过的成员、插过的适配节点还能不能当普通流程跑。能，就是工作台；不能，就是绑死在一个超级 Agent 上。

## 3. 熔炉出现在哪（已决方向）

不是常驻中栏、取代群聊的神助手，也 **不是工具箱**。熔炉 = Grok Agent + 一套适配提示词。

### 3.0 熔炉里没有工具

不在熔炉内维护「各种节点工具」列表或插件。用户看到的就是一个 Grok Agent。要接 CLI / 脚本，由提示词让它去 **改代码** 或 **往流程里加适配节点**，结果落在工作台的成员表和节点列表里。

### 3.1 添加成员时：改代码做适配

人手填脚本路径、工作目录仍然保留。可选交给熔炉：用适配提示词让 Grok **改代码**（包装脚本、打开 JSONL 侧通道、改成员 command / cwd 等），把外面的执行体收成普通 `script` / 终端成员。产出不是「熔炉私有工具」，过闸门后与手建成员相同。

### 3.2 添加节点时：增加适配节点做适配

在群流程里加步骤时，可选插入一个 **适配节点**（由熔炉按提示词生成并写入流程）。该节点负责把上一步/指定工具接到工作台契约（例如 JSONL、闸门、结果写回），而不是在熔炉聊天窗里内嵌那个工具。适配节点跑完仍是普通节点记录。

### 3.3 添加新群聊 / 群模板时可用

可选请熔炉按提示词拼成员和步骤（其中可含适配节点）。产出仍是普通群模板：关掉熔炉后群还能开聊、还能跑。

### 3.4 闸门可配置成熔炉

闸门执行者可配：**人**（默认）或 **熔炉**（Grok Agent）。需要人盯的步骤继续配人；适配方案审核、要不要写入成员/适配节点，可以配熔炉。闸门还是闸门，只是执行者多了一种。

## 4. 两条适配路径（已决）

熔炉只做一件事的两种落点：**用提示词让 Grok 做适配**。

| 入口 | 熔炉怎么做 | 落到工作台上的是什么 |
|------|------------|----------------------|
| **添加成员** | 提示词驱动 Grok **改代码**（包装、JSONL、成员配置） | 普通成员；可独立跑 PTY |
| **添加节点** | 提示词驱动 Grok **增加一个适配节点** | 流程上的普通节点，不是熔炉内插件 |

不另做「熔炉工具市场」。写代码、跑构建仍走工作台 PTY（Grok Build 作模型/执行来源），不在熔炉窗里藏一套无节点的执行。

提示词分册（加人适配 / 加节点适配 / 闸门上的熔炉）后细化，本文只锁「有提示词、无内置工具」。

## 5. 桌面形态：就叫熔炉（简易桌面版 Grok Build）

### 5.1 已决命名

桌面随叫随到的助手 **产品名就是熔炉**，不再使用「桌面精灵」作正式名称。托盘、小窗、热键唤起的都是熔炉；工作台三栏 + 内嵌 TUI 仍叫 oh-my-co-work（终端守护者）。**可切换的是形态，名字不换两套。**

体感接近简易桌面版 [Grok Build](https://grok.com) 式编码助手——能叫来、能改代码、能跑构建——但账本仍是本机群聊工作台。

### 5.2 和主题的关系：不必然偏离，但有条件

**不偏离**，若同时满足：

- 熔炉桌面与工作台共用本机 server、同一会话、同一成员、同一闸门和终端。  
- 熔炉里没有工具；加人走改代码适配，加节点走适配节点，结果都进工作台。  
- 写代码仍进 PTY 与（若有）JSONL，而不是桌面窗自己藏一份无账本的执行。  
- 用户可切回完整三栏工作台（群聊 + 流程轨 + 终端），熔炉桌面不是唯一入口。

**会偏离**，若变成：

- 只有熔炉小窗聊天，群、成员、闸门都成了后台细节。  
- Grok 云端会话与本机 Workflow 两套账。  
- 熔炉绕过闸门直接改成员或推进节点。  
- TUI 终端降级成调试窗，不再是一等执行载体。

结论：**熔炉 = 带适配提示词的 Grok Agent（工作台可配 + 桌面同名）；Grok Build 是模型来源。** 产品中心仍是群聊工作台。

### 5.3 形象 Logo（已决方向）

熔炉桌面/托盘用独立角色标，**不替代** 工作台 [人·文档·机](./brand-logo.md) Logo。

| 项 | 已决 |
|----|------|
| 主体 | 卡通 **黑裙美少女**（熔炉的精灵形象） |
| 画风 | **尽量极简**，少线、少装饰、少五官堆砌；靠剪影和黑裙块面出感染力 |
| 感染力 | 一眼能叫得出「是熔炉」，安静但不弱；避免二次元贴纸堆、避免写实 |
| 状态 | 必须有 **闲置** 与 **工作** 两套（可为两帧静态，或极简循环） |

**闲置**：待命、可点；姿态收、动势小（例如静立/微侧），黑裙为主色，不暗示正在改文件。用于托盘默认、未接任务、等人点。

**工作**：正在按提示词适配（改代码或写适配节点）；动势比闲置多一档即可（例如发梢/裙摆一线、手边一点工作提示），仍极简，禁止进度条脸、禁止工具图标挂一身。用于 Grok 推理中、改代码中、写节点中。

资产后置（3.3 前产出）：闲置 / 工作各至少一帧；托盘小尺寸可读；浅色与深色桌面都能认。具体发型、脸型、是否眨眼后细化，本文只锁「黑裙美少女 + 极简感染力 + 两态」。

### 5.4 必须写明的风险

| 风险 | 说明 | 应对方向（后细化） |
|------|------|-------------------|
| 本地优先 vs 云模型 | 2.x 数据在本机；Grok Build 通常要云端 API | 熔炉调用云模型可配；会话、代码、终端日志默认仍落本机；密钥不进 Adapter JSONL |
| 双形态分裂 | 桌面一套操作，工作台另一套 | 同一 REST/WebSocket；桌面只是薄壳 |
| 神 Agent | 所有闸门都配熔炉，人消失 | 默认闸门仍是人；熔炉是可选项 |
| 供应与条款 | Grok / Grok Build 接口、配额、地域会变 | 模型提供方做成可替换；熔炉不写死单一厂商于引擎内核 |
| 桌面壳技术 | 原设计已有 GUI 壳后置 | 与技术设计中的桌面壳合并为「熔炉」桌面形态，避免三个壳 |

## 6. 非目标（3.x 也不做或明确后置）

- 用熔炉替换 JSONL 契约，或解析终端画面充当 Adapter。  
- **在熔炉内做工具箱 / 插件市场**（没有「熔炉里的工具」）。  
- 多人同时控制同一 PTY（2.x 已非目标）。  
- 条件分支 / 并行画布（1.x 后置，不因熔炉提前做）。  
- 熔炉默认拥有全部闸门批准权。  
- 纯云端托管工作台（与本地优先冲突，除非另开产品线）。

## 7. 名词

| 词 | 含义 |
|----|------|
| Adapter | 融合**契约**：可信 JSONL 侧通道。门。 |
| 熔炉 | **Grok Agent**：靠提示词做适配；工作台可配到加人、加节点、建群、闸门；桌面同名随叫随到。**无内置工具。** 桌面形象为极简卡通黑裙美少女（闲置 / 工作两态）。 |
| 适配节点 | 添加流程步骤时由熔炉插入的普通节点，负责把某工具接到工作台契约。 |
| 终端守护者 / 工作台 | oh-my-co-work 三栏 + 内嵌 TUI；与熔炉桌面可切换。 |
| Grok / Grok Build | 熔炉所用的 Agent 模型与编码/构建来源；对接方式后细化。 |

## 8. 开放问题（后细化）

- 加人适配与加节点适配两套提示词如何分册、版本如何升级。  
- 适配节点的 `step_type` 是新类型还是复用 `member` + 标记。  
- 闸门执行者配置：仅「人 | 熔炉」，还是任意成员？  
- Grok 鉴权放本机设置还是环境变量；无密钥时熔炉如何降级（只适配、不写代码）。  
- 熔炉桌面用现有「打开本机 UI」还是独立小窗 + 托盘。  
- 工作台 ↔ 熔炉桌面切换是窗口级还是同一页内形态开关。  
- 黑裙形象的发型、正侧脸、是否循环动画（仍须极简）。

## 9. 讨论来源

2026-08-18 产品讨论纪要（已收口进本文，不另开聊天记录）：

- 2.x Adapter 的意义是翻译「终端里发生的事」→「工作台账本」；通用靠 JSONL 契约，不靠为每个 CLI 写解析器。  
- 熔炉是 **Grok Agent，里面没有工具**；靠提示词做适配。  
- **添加成员**：改代码做适配。**添加节点**：增加一个适配节点做适配。  
- 桌面形态 **就叫熔炉**；**保留工作台 TUI，可切换**。  
- 熔炉精灵形象：卡通黑裙美少女，极简有感染力，**闲置 / 工作**两态。  
- 约束：熔炉不是工具箱，也不是新的工作台中心。
