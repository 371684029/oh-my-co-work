## 1. 数据怎么存（原则 · 已决）

### 1.1 三层分工（写死，避免两套真相）

| 层 | 载体 | 存什么 | 原则 |
|----|------|--------|------|
| **A. 运行与配置库** | SQLite | Session、节点状态、**节点 input_json/output_json**、消息、成员/群、归档元数据 | **调度与查询的唯一真相**；可事务 |
| **B. 进程维护文档** | `journals/**/*.md` | 每节点输入/输出台账、会话 README 索引 | **给人读的真相**；程序可写、人可改 |
| **C. 大文件** | `artifacts/`、`logs/`、`uploads/` | 截图、包、stdout 全文、会话附件 | **只追加/尽量不可变**；库内只存路径引用 |

### 1.1.1 节点输入/输出怎么存（已落地）

| 层 | 存什么 | 路径 / 字段 |
|----|--------|-------------|
| **SQL** | 结构化 input / output | `node_instances.input_json`、`output_json`、`journal_path` |
| **Markdown** | 可读台账（YAML 头 + 输入/输出正文） | `journals/sessions/{sessionId}/nodes/step-XX-{nodeId}.md` |
| **索引** | 归档后会话总览 | `journals/sessions/{sessionId}/README.md` |

**原则**：列表/闸门/展开查看以 **SQL** 为准；MD 给人读与 Git；长 stdout 仍可在 `output.data` / `logs/` 引用。  
**UI**：右侧流程轨点击节点 **展开** 查看输入/输出（进行中与**归档后**均可）。

### 9.1 脚本上下文注入（人先说 → 再给脚本）

#### 已决原则（勿再纠结）

| # | 原则 | 说明 |
|---|------|------|
| 1 | **人优先** | 会话起手先走人工步（`captureParams`），收齐项目信息后再进成员脚本 |
| 2 | **SQL 为调度真相** | 参数只信 `sessions.context_json`（`params` / `paramsList` / `groupCard` / `groupFolder`…）；MD 给人读 |
| 3 | **脚本侧三路契约** | 见下表；**优先用 A + B**，C 为可选增强 |

#### 注入契约（推荐组合）

| 路径 | 形态 | 现状 | 说明 |
|------|------|------|------|
| A. 占位符 | 命令/参数/echo 模板里写 `#a`、`#1`、`{#1}`、`#群聊`、`#文件夹`、`{folder}` 等 | **已有** | `applyParamPlaceholders`；`#a`=调用时输入框参数 |
| **B. 环境变量** | `ACW_PARAM_1`、`ACW_PARAM_#1`、`ACW_PARAMS_JSON`、`ACW_SESSION_ID`、`ACW_MEMBER_ID`、`ACW_HUMAN_INPUT`；cwd 走 `#文件夹`/工作目录解析 | **已有** | 脚本语言无关；复杂参数优先读 `ACW_PARAMS_JSON` |
| **C. 上下文文件** | 跑脚本前写 `context.json`（或会话 journals 下同名）到 `#文件夹` | **未做** | 大段结构、多语言共用一份文件时再上；**不要**另搞第二套真相，内容仍从 `context_json` 导出 |

**推荐默认**：配置/命令用 **A**；正式 bat/ps1/py 读 **B**；只有「脚本生态只认文件」时再做 **C**。
