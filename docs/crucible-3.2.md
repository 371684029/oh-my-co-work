| 属性 | 内容 |
|------|------|
| 目标版本 | `3.2` |
| 状态 | **管理模型已收口；节点一览已接线** |
| 日期 | 2026-08-18 |
| 前置 | [crucible-3x.md](./crucible-3x.md)；群模板 + 节点实例 |
| 对照 | 脚本仍走 [data-and-ops.md](./data-and-ops.md) §9.1 的 `#` / `ACW_*` |

「工作总结」只是填槽的一个例子。3.2 管的是：**Agent 在一条工作流里，怎么知道每个节点是什么、现在该读哪一层 prompt、不许越权去跑别的节点。**

原计划里的「Grok 客户端」后置，见 [crucible-3x-plan.md](./crucible-3x-plan.md)。

---

## 1. 要管的不是场景，是节点

工作台的真相是群模板展开成的 **节点序列**（`node_instances`）。Agent 要懂的是地图，不是某一个业务名词：

- 第 1 步是人工填参，还是某个 CLI 成员？
- 哪一步勾了适配、哪一步要人闸 / 熔炉闸？
- 游标在哪？已经跑完的产出是什么？还没到的节点只是地图，不要提前执行。

用户不会在设置里给每个节点写一篇「系统提示」。人能配的还是工作台已有字段：群标题/简介、步骤标题、类型、成员、是否适配、闸门。**Prompt 工程 = 引擎按节点编译出 Agent 能读的合同**，不是再做一套 prompt CMS。

---

## 2. 谁在管哪一层

四层分开，别揉进同一个编辑器。

```
┌─────────────────────────────────────────────┐
│ ① 角色壳（仓库 prompts/ + 本机 memory/）      │  工程师维护；一次只装一套
│    主持 / 成员适配 / 节点适配 / 系统审核         │
├─────────────────────────────────────────────┤
│ ② 工作流地图（节点一览，本场会话编译）          │  引擎维护；每个节点是什么
│ ③ 当前节点合同（游标所在那一行的放大）          │  引擎维护；只许动这一格
├─────────────────────────────────────────────┤
│ ④ 成员脚本契约（#1 / ACW_* / cwd）            │  2.x 已有；给脚本，不给熔炉角色壳
└─────────────────────────────────────────────┘
```

| 层 | 管理者 | 变不变 | Agent 拿它干什么 |
| --- | --- | --- | --- |
| 角色壳 | 仓库里的 md | 慢 | 你是主持还是适配还是审核；禁止清单 |
| 工作流地图 | 群模板 + 节点状态 | 每场、每步刷新 | **哪个节点是什么** |
| 当前节点合同 | 游标 + 该步配置 + 上一产出 | 游标一动就换 | 这一格的任务边界 |
| 脚本契约 | 成员配置 | 跟脚本走 | CLI 读参数；熔炉不要抢 |

本机 Grok 仍只认 `data/furnace/ACTIVE.md` = ① + ② + ③ + 当前角色记忆。脚本成员继续只走 ④。两套通道，避免「把熔炉 system prompt 偷偷塞进 python」。

用户原话（开聊输入、后来的 `#1`）进地图的「意图 / 参数」槽，**不论这场是总结、发布、修脚本还是别的。**

## 3. 节点名片（地图的一行）

每个节点编译成固定字段。缺的写「—」，不删列，方便模型形成习惯。

| 字段 | 从哪来 | 作用 |
| --- | --- | --- |
| `#n` / `step_id` | 顺序 + 模板 id | 稳定指称「第 2 步」 |
| 标题 | `step.title` | 人起的名字 = 这格是什么 |
| 类型 | `step_type`：成员 / 人工 / 临时协助 | 谁该动手 |
| 执行者 | 成员展示名 | 具体哪个 Agent/脚本 |
| 标记 | 适配、人闸、熔炉闸 | 这格会不会换角色壳 |
| 状态 | 节点 SQL：待跑 / 执行中 / 待确认 / 完成 / 失败 | 游标与历史 |
| 游标 | 是否「现在」 | 合同只放大这一行 |

落在情境包里长这样：

```markdown
节点一览：
  #1 [人工 · 人闸] 填项目信息 · 完成
  #2 [成员 · 采集器 · 适配] 拉数据 · 执行中 ← 现在
  #3 [成员 · 熔炉] 整理结果 · 待跑
  #4 [人工 · 人闸] 确认 · 待跑
```

**当前节点**另起一段（合同，不是再抄一遍标题就完）：

```markdown
当前节点：#2 拉数据
它是什么：成员步骤 · 执行者 采集器 · 勾了适配
状态：执行中
上一节点产出：{短摘要或（无）}
合同：只处理当前节点。一览里其它行只是地图，不要提前执行、不要改编排。
```

判定有没有跑偏：Agent 能不能回答「现在是第几步、这一步是谁、下一步是什么、哪些已经完成」——靠地图，不靠猜群标题。

## 4. 游标怎么换壳（管理规则）

角色壳跟 **当前节点的标记** 走，不跟业务场景名字走。

| 当前节点 | 装哪套角色壳 | 地图 |
| --- | --- | --- |
| 普通推进、熔炉在场但未到闸/适配 | 群聊主持 | 照常刷新 |
| 该步勾了适配（步骤优先于仅成员勾选） | 节点适配 / 成员适配 | 留下；「现在」对准该步 |
| 闸门要熔炉确认 | 系统审核 | 留下；合同变成通过/拒绝这一格 |
| 用户在群里说话 | **保持当前壳** | 只更新意图/参数 |

禁止：因为群名叫「工作总结」就永远装主持；因为上一步是审核，下一步适配还沿用审核壳。

本机只有一个 Grok cwd → 后写覆盖。熔炉跟着**当前这场、当前游标**。

## 5. 编译原则（不要做成 prompt CMS）

- **槽位填充**，注入层不再调模型写摘要。
- **抄工作台已有字段**，不让用户再填一份平行的「节点系统提示」（与「是否适配」唯一选项冲突；后置才能谈 `step.hint`）。
- **地图全量、正文增量**：所有节点都在一览里；产出只对上一格做短摘要，全文去群报告指针。
- **脚本与熔炉分道**：`#` / `ACW_*` 给执行体；ACTIVE 给熔炉。
- **记忆不写本场事实**：记忆只准风格偏好；本场节点状态只活在情境包里。

截断：意图约 2k；单字段约 800；整份情境约 8k。超了留「…(截断)」+ 群报告路径。

## 6. 角色壳怎么读地图

| 角色 | 读完节点一览之后 | 仍然不许 |
| --- | --- | --- |
| 群聊主持 | 能指出每个节点是什么、游标在哪、缺哪一格的输入 | 改编排、改源文件、替闸门点通过 |
| 成员适配 | 当前节点的执行者是谁，把它接到工作台 | 去跑别的节点的业务、做审核 |
| 节点适配 | 当前这一格如何接到工作台；改不了就保留适配标记 | 改编排、做审核 |
| 系统审核 | 当前这一格的产出是否足以过闸 | 把未跑节点当完成、重写业务代码 |

主持是默认壳。适配/审核是游标落到带标记的格子时 **临时换壳**；换壳不换地图。

---

## 7. 和账本的关系

| 账本 | 谁的真相 | 编译进哪 |
| --- | --- | --- |
| 群模板步骤 | 每个节点「是什么」 | 节点一览 |
| `node_instances` 状态 | 走到哪 | 游标 / 状态列 |
| 开聊输入、`#1…` | 人这轮补充的事实 | 意图 / 参数槽 |
| 节点 output | 上一格结果 | 当前合同的「上一节点产出」 |
| `ANNOUNCEMENT.md` | 人读的长文 | 指针，不整篇复制 |
| 聊天气泡 | 过程 | 不进 ACTIVE 主上下文 |

关掉熔炉，流程仍按节点跑。熔炉只是多一份编译出来的 Markdown。

---

## 8. 不做 / 后置

- 不为每个节点在 UI 增加「系统提示」编辑框。
- 不新开 `step_type` / 气泡种类来承载 prompt。
- 不在注入层再调模型。
- 不把多场会话的地图拼进同一份 ACTIVE。
- `step.hint`（人给某一格的短备注）后置，且不能变成第二套编排语言。
- 精灵点开切壳、Grok 客户端：后置。

---

## 9. 验收

- 开聊后 `SITUATION.md` 能列出每个节点的类型、执行者、适配/闸门标记、状态，并标出「现在」。
- 换到适配步 / 熔炉闸门时，角色壳变、节点一览还在，「当前节点」对准那一格。
- 群标题叫什么都可以；地图不依赖「工作总结」这种场景词。
- `npm test` 覆盖节点一览编译与换壳保留地图。
